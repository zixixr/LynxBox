## 1. 产品概述

### 1.1 产品愿景 (Product Vision)

本项目旨在打造一款名为"LynxBox"的AI语音交互核心模组。通过将LynxBox永久植入毛绒玩具等传统物品中,我们能将其升级为具备智能对话、动作感知与情感交互能力的AI伙伴,为用户提供新颖、温暖的陪伴体验。

### 1.2 核心功能 (Core Features)

- **实时AI对话**: 基于云端AI服务,实现自然、流畅的语音对话交互
- **双麦克风打断**: 允许用户在AI回应过程中随时打断并输入新指令,模拟真实交流
- **动作感知交互**: 内置IMU传感器,可识别摇晃、翻转、轻拍等动作,并让AI在对话中做出相应反馈
- **无线连接与便捷配网**: 支持2.4GHz WiFi,通过蓝牙辅助手机APP/小程序快速完成网络配置
- **智能电源管理**: 包含低电量提醒、充电保护、自动休眠与唤醒等机制,确保安全与续航

### 1.3 关键技术规格 (Key Technical Specifications)

| 组件 | 规格 |
|------|------|
| **主控** | ESP32S3 模组 (Xtensa LX7双核, 240MHz, 512KB SRAM) - 具体型号待定 |
| **音频输入** | 双麦克风阵列(I2S接口,间距30-40mm) |
| **音频输出** | 内置扬声器(2-3W功率,频响300Hz-12kHz) |
| **传感器** | QMI8658 IMU惯性测量单元(6轴加速度+陀螺仪) |
| **连接性** | WiFi 2.4GHz (802.11 b/g/n), 蓝牙4.2 BLE |
| **物理交互** | 单个多功能按钮(支持短按/长按/超长按), LED指示灯 |
| **电源** | 1500-2000mAh锂聚合物电池,USB-C充电,电量检测电路 |
| **存储** | 4-8MB Flash (NVS分区存储加密配置) |

### 1.4 硬件版本规划 (Hardware Versions)

本产品设计两款硬件版本，除网络连接模块外其他硬件完全一致：

| 版本 | 网络模块 | 应用场景 | 附加要求 |
|------|---------|---------|---------|
| **WiFi版** | WiFi 2.4GHz + BLE | 家庭/办公室等有WiFi环境 | 成本优化，标准版 |
| **WiFi+4G版** | WiFi 2.4GHz + BLE + ML307 4G LTE (Cat.4, eSIM) | 户外/移动场景，无WiFi环境 | 信号强度优化，抗干扰设计，功耗<200mA活跃/<10mA休眠 |

**WiFi+4G版技术要求**：采用ML307 4G模块，信号覆盖主流运营商频段，PCB天线隔离设计减少干扰，支持eSIM Profile下载。网络切换逻辑：优先WiFi → WiFi不可用时切换4G → WiFi恢复后切换回WiFi。

### 1.5 数据隐私原则 (Data Privacy Principles)

- **无痕处理**: 所有用户的语音数据仅用于实时处理,不在设备端或云端进行任何形式的存储
- **加密传输**: 数据在传输过程中全程采用TLS/SSL加密,保障通信安全
- **本地化配置**: 仅在设备本地加密存储WiFi凭证等必要的非个人配置信息
- **合规认证**: 符合《个人信息保护法》等相关隐私保护规定

### 1.6 目标用户与使用场景

**主要客户**: 灵犀的毛绒玩具制造商
**最终用户**: 玩具购买者及使用者(全年龄段)

**典型使用场景**:
- 家庭陪伴: 作为日常对话伙伴,进行闲聊、讲故事、知识问答
- 情感互动: 通过语音和动作感知,提供情感回应和陪伴
- 多场景切换: 支持家庭/办公室等多WiFi环境自动切换

## 2. 用户场景与测试

### 用户故事 1 - 基本语音对话交互 (优先级: P1)

用户首次使用AI语音盒子与毛绒玩具进行语音对话。用户按下按钮开机，玩具发出欢迎提示音，用户直接对着玩具说话，玩具能够识别语音并通过内置扬声器回应，实现自然的双向对话交互。

**为什么是此优先级**: 语音对话是产品的核心价值主张，没有此功能产品无法使用。这是最小可行产品(MVP)的基础。

**独立测试**: 可通过开机后直接与玩具对话并接收语音回复来完整测试。交付价值:用户获得与玩具对话的基本体验。

**验收场景**:

1. **Given** 盒子处于关机状态, **When** 用户长按按钮3秒开机, **Then** 盒子播放开机音乐
2. **Given** 盒子已完成网络配置并开机, **When** 开机成功联网后, **Then** 盒子主动播放后台准备的"问候语"(如"你好,很高兴见到你")
3. **Given** 盒子已开机并完成网络配置, **When** 用户说"你好", **Then** 盒子在1.5秒内通过扬声器回应
3. **Given** 用户正在与盒子对话, **When** 用户在盒子说话过程中打断说"等一下", **Then** 盒子立即停止当前语音输出并等待新的用户输入
4. **Given** 盒子正在播放AI回应, **When** 用户摇晃玩具(IMU检测到动作), **Then** 盒子识别动作并在语音回应中提及"我感觉到你在和我玩"

---

### 用户故事 2 - 初次配网设置 (优先级: P2)

用户购买产品后,首次开机需要通过手机APP或小程序为盒子配置WiFi网络连接,使盒子能够访问互联网进行AI对话服务。

**为什么是此优先级**: 虽然是首次使用的必需步骤,但可以通过离线模式(预设对话)实现P1的基本测试。配网是产品正常使用的前提,但不阻碍核心功能演示。

**独立测试**: 可通过全新盒子从开机到成功连接WiFi的完整流程独立测试。交付价值:用户能够自主完成设备联网。

**验收场景**:

1. **Given** 盒子首次开机且未配置网络, **When** 开机完成, **Then** 盒子播放提示音"请使用手机APP连接我"并进入蓝牙配对模式
2. **Given** 盒子处于蓝牙配对模式, **When** 用户在手机APP中搜索并连接盒子蓝牙, **Then** APP显示"已连接设备"并显示可用WiFi网络列表
3. **Given** APP显示WiFi列表, **When** 用户选择家庭WiFi并输入密码点击连接, **Then** 盒子连接成功并播放提示音"网络连接成功",该WiFi凭证被保存
4. **Given** 盒子已配置1个或多个网络, **When** 盒子断电重启, **Then** 盒子自动扫描并连接已保存的可用WiFi网络(按信号强度优先)无需重新配置
5. **Given** 盒子配网失败(密码错误或信号弱), **When** 连接超时, **Then** 盒子播放提示音"网络连接失败,请重试"并保持蓝牙配对模式
6. **Given** 盒子已保存家庭和公司两个WiFi, **When** 用户带着玩具从家到公司, **Then** 盒子检测到家庭WiFi信号丢失后自动扫描并连接到公司WiFi
7. **Given** 用户需要添加新的WiFi网络, **When** 用户通过APP添加第3个WiFi, **Then** 新WiFi凭证被保存,盒子可存储并管理多个网络(至少支持10个)

---

### 用户故事 3 - 电源管理 (优先级: P3)

用户需要管理盒子的电源状态,包括充电提醒、低电量警告、以及正常关机,确保设备使用安全和良好的用户体验。

**为什么是此优先级**: 电源管理是产品可用性的重要保障,但不影响核心对话功能的演示和测试。可以在基本功能验证后再实现完整的电源管理逻辑。

**独立测试**: 可通过模拟不同电量状态(充电中、低电量、关机)独立测试。交付价值:用户能够安全使用和维护设备。

**验收场景**:

1. **Given** 盒子电量低于15%, **When** 电量触发低电警告, **Then** 盒子每隔5分钟播放提示音"电量不足,请充电"
2. **Given** 盒子正在使用, **When** 用户连接充电线, **Then** 盒子播放提示音"开始充电,充电期间请勿使用"并禁用所有对话和动作交互功能
3. **Given** 盒子正在充电, **When** 电量达到100%, **Then** 盒子播放提示音"充电完成"
4. **Given** 盒子处于开机状态, **When** 用户长按按钮5秒, **Then** 盒子播放关机音乐并语音提示"再见,下次见"后关闭电源
5. **Given** 盒子电量低于5%, **When** 电量耗尽, **Then** 盒子播放提示音"电量耗尽,即将关机"后自动关机

---

### 用户故事 4 - 设备重置与恢复 (优先级: P4)

用户在设备出现问题或需要转让设备时,能够通过按钮操作重置设备到出厂状态,清除所有个人配置和数据。

**为什么是此优先级**: 重置功能主要用于故障排除和设备转让场景,使用频率低,不影响日常使用和核心功能。

**独立测试**: 可通过执行重置操作并验证设备恢复到初始状态独立测试。交付价值:用户能够解决配置问题或安全地转让设备。

**验收场景**:

1. **Given** 盒子处于关机状态, **When** 用户长按按钮10秒, **Then** 盒子播放提示音"设备重置中,请稍候"
2. **Given** 重置流程启动, **When** 重置完成, **Then** 盒子清除所有WiFi配置、用户数据,并播放提示音"重置完成,设备已恢复出厂设置"后自动关机
3. **Given** 设备已重置, **When** 用户再次开机, **Then** 盒子表现如同全新设备,提示用户进行配网

---

### 用户故事 5 - 动作识别交互增强 (优先级: P5)

用户在与玩具对话时,通过摇晃、翻转、轻拍等物理动作与玩具互动,盒子通过IMU传感器识别这些动作,并在AI对话中做出相应反应,增强互动趣味性。

**为什么是此优先级**: 动作识别是锦上添花的增强功能,能显著提升用户体验和产品差异化,但不是基本对话功能所必需。

**独立测试**: 可通过执行特定动作(摇晃、翻转、轻拍)并验证AI回应是否包含动作相关内容独立测试。交付价值:用户获得更丰富、更有趣的互动体验。

**验收场景**:

1. **Given** 盒子处于对话模式, **When** 用户快速摇晃玩具3次, **Then** 盒子识别为"摇晃"动作并在对话中回应"哇,你在摇我,好好玩!"
2. **Given** 盒子处于对话模式, **When** 用户将玩具翻转180度(倒置), **Then** 盒子识别为"翻转"动作并回应"呀,我被翻过来了,好晕呀"
3. **Given** 盒子处于对话模式, **When** 用户轻拍玩具2次, **Then** 盒子识别为"轻拍"动作并回应"你在拍我吗?再来一次!"
4. **Given** 盒子处于空闲状态超过5分钟, **When** 用户拿起玩具(IMU检测到移动), **Then** 盒子主动语音问候"你回来啦,我们聊聊吧"

---

### 用户故事 6 - 动作唤醒交互 (优先级: P3)

用户在玩具处于休眠状态时,通过拿起或摇晃等动作直接唤醒设备,并立即开始互动,获得一种"即拿即玩"的无缝体验,无需寻找并按下小按钮。

**为什么是此优先级**: 这是提升产品"生命感"和易用性的重要功能,降低了交互门槛,增强了产品的主动性和灵性,但不影响核心对话流程的实现。

**独立测试**: 可通过将设备置于休眠状态,然后执行"拿起"动作,验证设备是否能被唤醒并主动问候。交付价值:降低了用户的交互门槛,增强了产品的灵性和主动性。

**验收场景**:

1. **Given** 盒子已联网并进入休眠状态, **When** 用户拿起玩具(IMU检测到持续位移), **Then** 盒子在2秒内被唤醒并主动播放问候语,如"你回来啦,我们聊聊吧!"
2. **Given** 盒子未联网并进入休眠状态, **When** 用户拿起玩具, **Then** 盒子被唤醒,并播放配网提示音"请使用手机APP连接我",同时进入蓝牙配对模式
3. **Given** 盒子处于休眠状态, **When** 用户摇晃玩具(快速摇晃≥2次), **Then** 盒子被唤醒,效果等同于"拿起"动作唤醒
4. **Given** 盒子通过动作唤醒后已联网, **When** 唤醒完成, **Then** 盒子自动重连WiFi并恢复到待机状态,准备接收语音输入

### 2.6 边界情况与异常处理

| 场景 | 系统行为 |
|------|----------|
| 用户持续打断(连续3次以上) | 正常响应每次打断,不做特殊处理 |
| WiFi信号丢失或网络中断 | 播放提示音"网络连接失败,请检查网络"并停止对话服务,直到网络恢复 |
| 云端AI服务超时/不可用 | 自动重试1次(总计2次,每次超时2秒),仍失败则播放"服务暂时不可用" |
| 蓝牙配对10分钟无连接 | 自动进入休眠状态,按按钮1秒可唤醒并重新进入配对模式 |
| 充电时电池温度>45°C | 立即停止充电并播放警告,降至40°C恢复;连续3次超温则停止充电并关机 |
| 充电期间用户尝试交互 | 播放提示音"充电期间请勿使用",不响应交互请求 |
| WiFi环境切换 | 自动检测信号丢失并扫描连接其他已保存WiFi,切换过程对用户透明 |
| 所有已保存WiFi不可用 | 播放提示音"网络连接失败"并进入蓝牙配对模式等待添加新网络 |
| 多麦克风输入(环境噪音/多人说话) | 优先处理信号强度最高、最稳定的麦克风输入,过滤远处背景噪音(需波束成形支持) |
| IMU检测剧烈震动(跌落) | 记录事件到日志,继续正常服务(无需暂停或自检) |
| 对话中断后恢复 | AI可主动询问"我刚才讲到一半,你还想继续听吗?"(上下文感知) |

## 3. 功能需求 (Functional Requirements)

### 3.1 硬件交互需求

**硬件交互需求**

- **FR-001**: 盒子必须支持通过单个外置按钮实现开机(长按3秒)、关机(长按5秒)、重置(关机状态下长按10秒)三种操作
  - *注: 按钮交互时长(3秒/5秒)待用户体验测试优化,可根据实际使用反馈调整*
- **FR-002**: 盒子必须通过双麦克风阵列实现实时语音输入,支持在播放音频时检测用户打断并立即停止播放(基于乐鑫AEC组件实现,详见技术约束)
- **FR-003**: 盒子必须通过内置扬声器播放AI语音回应、系统提示音、开关机音乐
- **FR-004**: 盒子必须通过IMU传感器实时检测并识别至少以下几种用户动作:拿起、摇晃(区分快速和温柔)、翻转、轻拍、静置、跌落(自由落体)
- **FR-004a (动作定义参考)**: 上述动作的算法具体实现(例如加速度阈值、角速度变化、持续时间等参数)在详细设计阶段,应重点参考Project Magic项目的相关定义与实现,以确保动作识别的准确性和交互体验的自然流畅。跌落动作应触发保护性或安抚性回应(如"哎呀,我摔倒了,你没事吧?")
- **FR-005**: 盒子必须支持通过USB接口进行充电,并在充电状态改变时播放相应提示音
- **FR-005a (LED状态指示)**: 盒子必须通过LED指示灯显示设备状态:
  - 充电中:LED呼吸灯效果(或红色常亮)
  - 充电完成:LED绿色常亮(或熄灭)
  - 充电异常(温度过高):LED红色闪烁
  - 说话状态(AI语音播放中):待定
  - 聆听状态(监听用户输入):待定
  - 待机状态:待定
  - *注: 说话、聆听、待机等工作状态的LED效果(颜色、闪烁模式、呼吸效果等)将在详细设计阶段定义*

**网络与连接需求**

- **FR-006**: 盒子必须支持2.4GHz WiFi(802.11 b/g/n)网络连接
- **FR-007**: 盒子必须在首次开机或未配置网络时自动进入蓝牙配对模式,广播蓝牙信号供手机APP/小程序连接
- **FR-008**: 盒子必须在成功配对后,通过蓝牙接收来自手机APP的WiFi凭证(SSID和密码)并尝试连接
- **FR-009**: 盒子必须在WiFi连接成功后播放成功提示音并保存该网络凭证,连接失败后播放失败提示音并保持蓝牙配对模式
- **FR-010**: 盒子必须支持存储多个WiFi网络凭证(至少10个),每个凭证包含SSID、密码(加密存储)、上次连接时间
- **FR-010a**: 盒子在开机或网络断开时必须自动扫描周围WiFi,优先连接已保存网络中信号强度最强的可用网络
- **FR-010b**: 盒子在当前WiFi信号丢失时,必须自动扫描并尝试连接其他已保存的可用WiFi网络,无需用户干预
- **FR-010c**: 盒子必须支持通过APP管理已保存的WiFi网络,包括添加新网络、删除已保存网络、查看已保存网络列表

**语音交互需求**

- **FR-011**: 盒子必须能够采集用户语音输入并通过网络传输至云端ASR服务进行语音识别,将识别结果(文本)用于AI处理
- **FR-012**: 盒子必须能够接收云端TTS服务生成的语音数据并通过扬声器播放
- **FR-013**: 盒子必须支持两种打断模式:
  - **模式1-关键词打断**: 当用户说出特定关键词(如"等一下""停一下""暂停")时,盒子立即停止播放并等待新输入
  - **模式2-语音检测打断**: 只要双麦克风检测到用户开始说话(基于AEC处理后的语音能量检测),盒子立即停止播放
- **FR-013a**: 打断模式可通过云端配置选择,默认使用模式2(语音检测打断),响应时间≤500ms
- **FR-014**: 盒子必须在检测到用户动作(通过IMU)时,将动作信息作为上下文传递给AI,使AI回应能够关联用户动作
- **FR-015**: 盒子必须在网络连接正常时提供完整的在线AI对话服务
- **FR-015a**: 盒子在网络未连接或中断时,必须播放提示音"网络未连接,请先配置网络"或"网络连接失败,请检查网络",不提供对话服务
- **FR-015b**: 盒子在云端AI服务请求失败或超时(超时阈值2秒)时,必须自动重试1次,若仍失败则播放提示音"服务暂时不可用,请稍后再试"

**音频提示需求**

- **FR-016**: 盒子必须内置以下系统提示音:开机音乐、关机音乐、网络连接成功、网络连接失败、开始充电(含充电期间请勿使用提示)、充电完成、电量不足、电量耗尽、温度过高已停止充电、设备重置中、重置完成、请使用手机APP连接、服务暂时不可用
- **FR-017**: 盒子必须在特定系统事件触发时自动播放对应提示音(如开机时播放开机音乐)
- **FR-018**: 盒子必须确保系统提示音优先级高于AI语音播放,在播放提示音时暂停AI语音

**电源管理需求**

- **FR-019**: 盒子必须在电量低于15%时每隔5分钟播放一次低电量提示音
- **FR-020**: 盒子必须在电量低于5%时播放电量耗尽提示音并自动关机
- **FR-021**: 盒子必须在连接充电器时播放充电提示音"开始充电,充电期间请勿使用",断开充电器时停止充电指示
- **FR-022**: 盒子必须在充电完成(电量达100%)时播放充电完成提示音
- **FR-022a**: 盒子在充电状态下必须禁用所有交互功能(语音对话、按钮操作除外、IMU动作识别),仅允许断开充电器或长按5秒关机
- **FR-022b**: 盒子必须在充电过程中监测电池温度,当温度超过45°C时立即停止充电并播放警告提示音"温度过高,已停止充电",温度降至40°C以下时自动恢复充电
- **FR-022c**: 盒子在充电温度异常(连续3次超温保护)时必须停止充电并保持关机状态,需要用户拔出充电线等待冷却
- **FR-023**: 盒子必须在任何状态下(包括蓝牙配对模式、待机、对话空闲)连续10分钟无用户交互(无语音输入、无按钮操作、无IMU动作)时自动进入休眠状态
- **FR-024**: 盒子在休眠状态下必须关闭蓝牙广播、WiFi连接、麦克风监听,仅保持按钮唤醒和IMU动作唤醒功能(低功耗IMU监听模式)
  - *注: WiFi断开的省电效果需实测验证,若WiFi保持连接功耗增加不显著,可优化为保持WiFi连接以加快唤醒响应*
- **FR-025**: 用户在休眠状态下按按钮1秒必须唤醒盒子
- **FR-025a (动作唤醒)**: 在休眠状态下,当IMU检测到指定的唤醒动作(定义为"拿起"或"快速摇晃")时,设备也必须自动唤醒,其效果等同于按钮唤醒
- **FR-025b (唤醒后行为)**: 无论是通过按钮还是动作唤醒,设备恢复到休眠前的状态。若已配网,则重连WiFi并进入待机状态;若未配网,则进入蓝牙配对模式。唤醒后若网络可用,应主动发起问候语音(如"你回来啦,我们聊聊吧!")

**设备管理需求**

- **FR-026**: 盒子必须支持恢复出厂设置操作,清除所有保存的WiFi凭证(包括多个已保存网络)、用户配置和缓存数据
- **FR-027**: 盒子必须在重置完成后自动关机,下次开机时表现为全新设备状态
- **FR-028**: 盒子必须在重置过程中播放重置提示音,重置完成后播放完成提示音

**数据隐私需求**

- **FR-029**: 盒子必须通过加密连接(TLS/SSL)将语音数据实时传输到云端AI服务
- **FR-030**: 盒子本地不得存储任何用户语音数据(音频文件或转写文本)
- **FR-031**: 盒子重置操作必须清除所有可能包含用户信息的缓存数据(不包括固件和系统提示音)

**存储管理需求**

- **FR-033**: 盒子本地仅存储必要的系统数据:固件、系统提示音、多个WiFi凭证(加密存储,至少10个)、设备状态
- **FR-034**: 盒子不得存储对话历史、用户行为日志、或任何可累积增长的用户数据
- **FR-035**: 盒子的日志功能(如有)必须采用循环日志机制,日志文件总大小不得超过100KB,自动覆盖最旧记录
- **FR-036**: 盒子在存储WiFi凭证达到上限(10个)时,必须支持通过APP删除旧网络后添加新网络,或自动覆盖最久未使用的网络

### 3.2 离线/弱网交互增强需求

**设计理念**: 当网络不可用时,设备不应完全"失联",而是通过预设音效保持"生命感",提升弱网环境下的用户体验。

- **FR-037**: 盒子在离线状态下检测到IMU动作时,必须播放预设的非语言音效(如好奇的"嗯?"、开心的哼唱)作为反馈,而非保持沉默
- **FR-038**: 盒子必须支持为不同玩具角色配置专属音效库(如"小熊"角色摇晃时发出笑声,"机器人"角色发出机械音效)
- **FR-039**: 盒子在离线状态下被拿起时,应播放简短的问候音效,而非完全无响应
- **FR-040**: 离线音效优先级应低于系统提示音,但高于沉默状态,总音效数量≤10个,Flash占用<500KB

### 3.3 多语言支持需求

**设计理念**: 支持中英文系统提示语音,通过云端配置或固件配置灵活选择语言版本,满足国内外不同市场需求。

- **FR-045**: 盒子必须支持中文和英文两种语言的系统提示音,包括所有FR-016定义的提示音类型(开机音乐、关机音乐、网络连接成功/失败、充电相关、电量提示、设备重置等)
- **FR-046**: 盒子必须在固件烧录阶段通过menuconfig配置默认语言版本(中文版/海外版),烧录后系统提示音默认使用对应语言
- **FR-047**: 盒子必须支持通过云端配置动态切换系统提示音语言,云端可针对特定批次设备标识目标市场(如"海外市场"),设备联网后自动下载并切换至对应语言的提示音
- **FR-048**: 云端语言配置优先级高于固件默认配置,即:若云端配置了语言版本,设备联网后自动应用云端配置;若云端未配置,则使用固件默认语言
- **FR-049**: 系统提示音语音包必须支持热更新,设备联网后可从云端下载新语言包并替换本地提示音,无需重新烧录固件
- **FR-050**: 语音包文件必须采用OGG格式Opus封装,每种语言的完整语音包大小≤1MB,支持中英文两种语言时总占用≤2MB

**实现说明**:
- 固件menuconfig提供语言选项: `CONFIG_LANG_CN`(中文版) / `CONFIG_LANG_EN`(海外英文版)
- 云端通过设备配置API下发语言标识,设备在联网时查询并应用
- 语音包存储在Flash独立分区,支持动态替换

### 3.4 上下文感知与交互优化需求 (云端)

**设计理念**: 通过上下文记忆和环境感知,让交互更智能、更自然。

- **FR-041**: 盒子在AI回应被用户打断后,将打断事件信息发送至云端,由云端AI决定是否主动询问"我刚才讲到一半,你还想继续听吗?"
- **FR-042**: 盒子应支持连续动作识别(如连续轻拍3次触发彩蛋,摇晃+翻转识别为组合动作),并给予特殊反馈
- **FR-043**: 盒子在深夜时段(0:00-6:00,需从云端获取时间戳)被唤醒时,将时段信息发送至云端,由云端AI生成更温柔的问候语(如"这么晚还没睡吗?")
- **FR-044**: 对话上下文记忆由云端AI服务处理,盒子不保存对话历史

### 3.5 关键实体

- **语音会话**: 表示一次完整的用户与AI的对话交互,包含动作上下文、时间戳等属性(注:不包含语音数据本身,语音数据实时处理后立即丢弃;不保存历史记录)
- **网络配置**: 存储多个WiFi网络凭证(至少10个),每个包含SSID、密码(加密存储)、上次连接时间、信号强度等属性,持久化保存在设备本地
- **设备状态**: 表示盒子当前的运行状态,包含电量百分比、网络连接状态、蓝牙配对状态、充电状态、音频播放状态、温度状态等属性,运行时状态不持久化。设备状态需要上报云端,后续在APP端显示
- **用户动作**: 表示IMU传感器检测到的用户物理交互,包含动作类型(摇晃/翻转/轻拍/静置)、动作强度、时间戳等属性,实时传递给AI后不保存
- **系统提示音**: 预置的音频文件资源,包含提示音类型、音频文件路径、播放优先级等属性,固化在固件中
- **循环日志**: (可选)用于故障诊断的临时日志,固定大小100KB,采用循环覆盖机制,不保存用户隐私数据

## 4. 非功能性需求 (Non-Functional Requirements)

本章节整合所有性能、可靠性、安全性和易用性相关的量化指标,为测试和运维团队提供明确的质量评估标准。

### 4.1 性能需求 (Performance)

**NFR-001 语音交互响应时间**
- **指标**: 用户说话结束到AI开始播放回应的端到端延迟 ≤ 2秒
- **测试条件**: 正常网络环境(延迟<100ms,丢包率<1%),WiFi信号≥-70dBm
- **降级策略**: 若网络延迟>200ms,允许延迟增至3秒;若延迟>5秒,触发重试机制
- **关联需求**: SC-002, FR-015

**NFR-002 打断检测响应时间**
- **指标**: 检测到用户打断到停止播放的响应时间 ≤ 500毫秒
- **测试条件**: 双麦克风波束成形正常工作,环境噪音<60dB
- **技术实现**: 双麦克风阵列实时检测语音能量峰值,触发播放中断
- **关联需求**: SC-003, FR-013

**NFR-003 WiFi自动切换速度**
- **指标**: 当前WiFi信号丢失后,30秒内自动连接其他已保存网络
- **测试条件**: 至少保存2个可用WiFi,备用WiFi信号≥-75dBm
- **降级策略**: 若所有已保存WiFi不可用,播放提示音并进入蓝牙配对模式
- **关联需求**: SC-005a, FR-010b

**NFR-004 休眠与唤醒性能**
- **休眠触发**: 连续10分钟无交互自动进入休眠状态
- **休眠功耗**: 休眠功耗 ≤ 待机功耗的10% (目标<10mA)
- **唤醒速度**: 从休眠到可用状态 ≤ 2秒 (包含WiFi重连)
- **关联需求**: SC-009, FR-023, FR-024, FR-025

**NFR-005 IMU动作识别准确率**
- **指标**: 针对摇晃、翻转、轻拍三种主要动作,识别准确率 ≥ 85%
- **测试方法**: 每种动作重复测试20次,准确识别次数/总次数
- **误识别容忍**: 静置状态下误触发率 < 5% (避免无动作时频繁误识别)
- **关联需求**: SC-004, FR-004

**NFR-006 系统提示音及时性**
- **指标**: 系统事件触发后1秒内开始播放对应提示音
- **覆盖场景**: 开机/关机/充电/网络连接/电量警告等13种提示音
- **优先级**: 系统提示音优先级高于AI语音,播放时暂停AI输出
- **关联需求**: SC-008, FR-017, FR-018

### 4.2 可靠性需求 (Reliability)

**NFR-007 WiFi连接成功率**
- **指标**: WiFi信号强度≥-70dBm时,连接成功率 ≥ 95%
- **测试样本**: 100次连接尝试(包含开机、切换网络等场景)
- **失败处理**: 连接失败播放提示音,保持蓝牙配对模式等待用户干预
- **关联需求**: SC-005, FR-009

**NFR-008 云端服务容错**
- **超时阈值**: 单次API请求超时阈值设为2秒
- **重试策略**: 请求失败或超时自动重试1次(总计2次尝试)
- **降级提示**: 重试后仍失败,播放"服务暂时不可用,请稍后再试"
- **关联需求**: FR-015b

**NFR-009 充电安全与保护**
- **温度监测**: 充电时实时监测电池温度,采样频率≥1次/秒
- **过温保护**: 温度>45°C立即停止充电并播放警告,降至40°C自动恢复
- **多次超温**: 连续3次超温保护触发后,停止充电并关机,需用户拔线冷却
- **关联需求**: FR-022b, FR-022c

**NFR-010 多WiFi管理可靠性**
- **存储容量**: 至少支持保存10个WiFi网络凭证,超过上限时自动覆盖最久未使用的网络
- **自动选择**: 开机/断网时,优先连接信号最强的已保存网络
- **覆盖策略**: 达到上限时,支持APP删除旧网络或自动覆盖最久未使用网络(需用户确认)
- **关联需求**: FR-010, FR-010a, FR-036

### 4.3 安全性需求 (Security)

**NFR-011 数据传输加密**
- **加密协议**: 所有网络通信必须使用TLS/SSL加密(TLS 1.2+)
- **证书验证**: 云端API通信需验证服务器证书,防止中间人攻击
- **覆盖范围**: 语音数据上传、AI回应下载、配置同步等所有网络交互
- **关联需求**: FR-029

**NFR-012 零用户数据存储**
- **设备端**: 不存储任何用户语音数据(音频文件或转写文本)
- **云端**: 语音数据处理完成后立即删除,不保留任何记录或日志
- **审计要求**: 可通过代码审计和网络流量监控验证合规性
- **关联需求**: FR-030, FR-031, 数据隐私原则(1.4)

**NFR-013 WiFi凭证保护**
- **加密存储**: WiFi密码使用AES-256加密后存储于NVS分区
- **访问控制**: 仅授权固件模块可访问加密凭证,禁止外部读取
- **重置清除**: 恢复出厂设置时完全清除所有加密凭证
- **关联需求**: FR-026, FR-032

**NFR-014 隐私合规认证**
- **法规遵循**: 符合《中华人民共和国个人信息保护法》等相关法律
- **认证要求**: 产品发布前需通过第三方隐私合规审计
- **数据本地化**: 使用国内AI服务提供商,数据处理不出境
- **关联需求**: 数据隐私原则(1.4), 业务约束

### 4.4 易用性需求 (Usability)

**NFR-015 首次使用体验**
- **指标**: 用户从开机到完成首次语音对话(含配网)总时长 ≤ 3分钟
- **无说明书操作**: 90%的用户能够在无说明书情况下独立完成首次配网
- **引导提示**: 通过系统语音提示引导用户完成开机、配网、首次对话
- **关联需求**: SC-001, SC-007

**NFR-016 续航与电源体验**
- **续航时间**: 中等使用强度(每小时对话10分钟)下,单次充电续航 ≥ 6小时
- **低电量提醒**: 电量<15%时每5分钟播放一次提醒,<5%时自动关机前提醒
- **充电反馈**: 充电状态变化时及时播放提示音(开始充电/充电完成/温度异常)
- **关联需求**: SC-006, FR-019, FR-020, FR-021, FR-022

**NFR-017 交互反馈清晰度**
- **语音提示**: 所有系统事件(开机/关机/充电/网络/错误)均有对应语音提示
- **音效区分**: 成功/失败/警告等不同类型事件使用可区分的音效设计
- **音量适中**: 系统提示音音量适中,不刺耳,符合家庭使用场景
- **关联需求**: FR-016, FR-017, NFR-006

### 4.5 可维护性需求 (Maintainability)

**NFR-018 日志与诊断**
- **循环日志**: 采用固定100KB循环日志,自动覆盖最旧记录
- **隐私保护**: 日志仅包含系统事件和错误信息,不记录用户语音或对话内容
- **故障诊断**: 记录网络连接失败、API超时、传感器异常等关键事件
- **关联需求**: FR-035, 关键实体-循环日志

**NFR-019 设备重置可靠性**
- **完整清除**: 重置操作清除所有WiFi凭证、配置和缓存数据
- **保留固件**: 重置不影响固件和系统提示音资源
- **重置确认**: 重置操作需特定长按时长(10秒),避免误触发
- **关联需求**: FR-026, FR-027, FR-028

### 4.6 硬件约束与技术指标 (Hardware Constraints)

**NFR-020 双麦克风阵列规格**
- **麦克风间距**: 待定 (需参考乐鑫官方AEC文档确认最佳间距,用于波束成形和方向性检测)
- **采样率**: 16kHz单声道
- **信噪比**: ≥60dB (确保语音清晰度)
- **回声消除(AEC)**: 必须基于乐鑫(Espressif)官方AEC组件实现,支持扬声器播放时麦克风回声消除,防止循环反馈,确保打断(Barge-in)功能可靠性
- **波束成形**: 利用双麦克风相位差进行方向性增强,抑制侧向噪音
- **噪声抑制**: 环境噪音<60dB时,能有效提取人声信号
- **打断检测**: 基于AEC处理后的语音能量检测,在扬声器播放期间实时监测用户语音输入

**NFR-021 IMU传感器动作定义**

*注: 以下参数为初步定义,详细实现应参考Project Magic项目的经验数据*

- **拿起检测**: 三轴合成加速度从静置状态(<0.2g)突然上升至>0.5g并持续>500ms,识别为拿起动作,用于休眠唤醒或主动问候
- **摇晃检测(快速)**: X/Y轴加速度变化频率>2Hz,振幅>1.0g,持续时间≥1秒,识别为快速摇晃,可用于唤醒或触发兴奋回应
- **摇晃检测(温柔)**: X/Y轴加速度变化频率1-2Hz,振幅0.3-1.0g,持续时间≥2秒,识别为温柔摇晃,触发温和回应
- **翻转检测**: Z轴角度变化≥180°,速率适中(0.5-2秒完成翻转),识别为翻转
- **轻拍检测**: Z轴加速度瞬时峰值>1.5g,出现2次明显峰值(间隔<500ms),识别为轻拍
- **跌落检测**: 三轴合成加速度同时接近0g(自由落体),持续>100ms,识别为跌落,触发安抚性回应
- **静置检测**: 三轴加速度变化<0.1g持续≥30秒,识别为静置
- **组合动作**: 连续识别多个动作(如摇晃+翻转),触发特殊反馈或彩蛋
- **算法参考**: 详细阈值调优和滤波算法应参考Project Magic项目的实现经验

**NFR-022 音频编解码规格**
- **编码格式**: Opus (开源,低延迟,高压缩率)
- **码率**: 32kbps (语音质量与带宽的平衡点)
- **采样率**: 16kHz单声道
- **帧长**: 20ms (320字节/帧未压缩,约80字节/帧压缩后)
- **延迟**: 编解码总延迟<50ms

**NFR-023 存储空间分配**
- **固件分区**: 待定 (包含应用代码和库,需根据最终ESP32S3模组选型确定)
- **系统提示音**: ≤2MB (13个音频文件 × 2种语言,OGG格式Opus封装,单语言包≤1MB)
- **NVS配置**: ≤512KB (WiFi凭证、设备配置、语言设置等)
- **OTA预留** (未来): ≤4MB (双分区方案,支持安全升级)
- **总Flash**: 4-8MB (ESP32S3标准配置)

**NFR-024 多语言支持技术规格**
- **语言种类**: 支持中文和英文两种语言
- **切换方式**: 支持固件编译时配置(menuconfig)和云端动态配置两种方式
- **配置优先级**: 云端配置 > 固件默认配置
- **语音包格式**: OGG格式Opus封装,单语言包大小≤1MB
- **热更新机制**: 设备联网后可从云端下载新语言包并替换本地提示音,下载失败时回退至当前语言包
- **存储位置**: 语音包存储在Flash独立分区,支持动态替换不影响固件区
- **切换延迟**: 云端下发语言配置后,设备在下次联网时应用新语言,切换过程无需重启
- **关联需求**: FR-045至FR-050

**NFR-025 网络通信协议**
- **WiFi标准**: 802.11 b/g/n (2.4GHz频段)
- **信号要求**: ≥-70dBm时保证稳定连接,<-85dBm时可能断开
- **蓝牙**: BLE 4.2 (低功耗蓝牙,仅用于配网)
- **传输协议**: WebSocket (语音流) + HTTP/HTTPS (控制消息)
- **带宽需求**: 上行32kbps (音频上传) + 下行32-64kbps (TTS下载)

## 6. 假设与依赖

### 6.1 技术假设

1. **AI服务可用性**: 假设存在可用的云端AI对话服务API,盒子通过WiFi网络访问该服务获取对话回应
2. **手机APP/小程序就绪**: 假设配套的手机APP或微信小程序已开发完成,能够提供蓝牙配对和WiFi配置功能
3. **语音识别与合成**: 假设采用行业标准的语音识别(ASR)和语音合成(TTS)服务,识别准确率和合成质量达到商用水平
4. **电池容量**: 假设盒子配备容量不低于1500mAh的锂电池,能够满足NFR-016定义的续航要求
5. **网络依赖**: AI对话服务完全依赖互联网连接,离线状态下通过预设音效保持基本交互体验(详见FR-037至FR-040)
6. **单用户使用**: 假设盒子主要为单个用户设计,不需要支持多用户账户或个性化配置(如未要求多用户功能)
7. **存储容量**: 假设ESP32S3模组配备足够的Flash存储空间(≥4MB),能够容纳固件、系统提示音和必要的系统数据,详见NFR-023
8. **环境噪音处理**: 假设双麦克风阵列具备基本的噪音抑制和回声消除能力,能够在典型家庭环境(噪音<60dB)下正常工作,详见NFR-020
9. **数据隐私**: 所有语音数据通过加密连接传输,处理后立即删除不保留,遵循中国《个人信息保护法》等相关隐私保护规定,详见NFR-012, NFR-014

### 6.2 依赖与约束

**外部依赖**

- 云端AI对话服务API的可用性和响应速度 → 详见NFR-008
- 手机APP/微信小程序的蓝牙和WiFi配置功能
- 用户家庭2.4GHz WiFi网络的可用性和稳定性 → 详见NFR-025
- 语音识别(ASR)和语音合成(TTS)第三方服务

**技术约束**

- ESP32S3模组的计算能力和存储空间限制 → 详见NFR-023
- **双麦克风阵列**: 阵列的噪音抑制和打断检测能力,必须基于乐鑫(Espressif)官方提供的AEC(Acoustic Echo Cancellation/声学回声消除)功能组件进行开发。这旨在确保在扬声器播放AI语音或其他音频时,依然能有效消除回声,准确捕捉用户的语音输入,从而实现可靠、低延迟的"打断"(Barge-in)功能 → 详见NFR-020
- 内置扬声器的音质和音量输出能力
- **IMU传感器**: 精度和采样频率要求,动作识别算法详细设计应参考Project Magic项目的相关定义与实现 → 详见NFR-021, FR-004a
- 蓝牙配对距离限制(典型<10米) → 详见NFR-025

**业务约束**

- 产品需符合电子产品安全标准(如GB 4943.1信息技术设备安全)
- 必须通过相关电子产品认证(如CCC、无线电型号核准SRRC)
- 隐私合规认证要求 → 详见NFR-014

## 7. 范围界定

### 7.1 包含在内 (Phase 1)

- 完整的语音对话交互功能(依赖网络)
- 蓝牙配对和WiFi配网流程
- 多WiFi网络管理与自动切换 (详见FR-010系列)
- 基本的电源管理(充电、低电量提示、开关机、休眠唤醒)
- IMU动作识别与AI对话的结合
- 系统提示音和引导语音
- 多语言支持(中英文系统提示音,支持固件配置和云端动态切换) (详见FR-045至FR-050)
- 设备重置功能
- 打断检测功能 (详见NFR-002)

### 7.2 明确排除

- 盒子本地的AI模型运行(所有AI处理在云端完成)
- 5GHz WiFi或以太网支持
- 触摸屏或额外的物理按钮
- 多设备组网或设备间通信
- OTA固件升级功能(初版,可在后续版本加入)
- 内容过滤或使用时长限制功能
- 与其他智能家居设备的联动
