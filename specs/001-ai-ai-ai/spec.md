## 1. 产品概述

### 1.1 产品愿景 (Product Vision)

本项目旨在打造一款名为"LynxBox"的AI语音交互核心模组。通过将LynxBox永久植入毛绒玩具等传统物品中,我们能将其升级为具备智能对话、动作感知与情感交互能力的AI伙伴,为用户提供新颖、温暖的陪伴体验。

### 1.2 核心功能 (Core Features)

- **实时AI对话**: 基于云端AI服务,实现自然、流畅的语音对话交互
- **双麦克风打断**: 允许用户在AI回应过程中随时打断并输入新指令,模拟真实交流
- **动作感知交互**: 内置IMU传感器,可识别摇晃、翻转、轻拍等动作,并让AI在对话中做出相应反馈
- **多模态反馈**: 结合语音、音效和触觉震动反馈,在未被语音/晃动唤醒时播放预设音效和震动,增强交互生命感
- **无线连接与便捷配网**: 支持2.4GHz WiFi,通过蓝牙辅助手机APP/小程序快速完成网络配置
- **智能电源管理**: 包含低电量提醒、充电保护、自动休眠与唤醒等机制,确保安全与续航

### 1.3 关键技术规格 (Key Technical Specifications)

| 组件 | 规格 |
|------|------|
| **主控** | ESP32S3 模组 (Xtensa LX7双核, 240MHz, 512KB SRAM, ≥8MB Flash) - 推荐8MB或16MB Flash型号 |
| **音频输入** | ES7210 ADC + 2个LMA3729T381-OY3S模拟麦克风(兼容MSM381A3729H9BPC), I2S接口, 间距45mm |
| **音频输出** | ES8311 Audio Codec + NS4150B功放 + XHXDZ-2828-4R3W-2P扬声器(4Ω 3W) |
| **传感器** | QMI8658 IMU惯性测量单元(6轴加速度+陀螺仪) |
| **触觉反馈** | 偏心转子振动电机(ERM/LRA可选), GPIO驱动, 支持震动强度和模式控制 |
| **连接性** | WiFi 2.4GHz (802.11 b/g/n), 蓝牙4.2 BLE |
| **物理交互** | 单个多功能按钮(支持短按/长按/超长按), LED指示灯, 触摸引脚预留(ESP32S3内置触摸传感器,最多支持14路) |
| **电源** | 1500-2000mAh锂聚合物电池,USB-C充电,电量检测电路 |
| **存储** | ≥8MB Flash (支持OTA双分区+资源分区,推荐8MB或16MB模组) |

### 1.4 硬件版本规划 (Hardware Versions)

本产品设计两款硬件版本，除网络连接模块外其他硬件完全一致：

| 版本 | 网络模块 | 应用场景 | 附加要求 |
|------|---------|---------|---------|
| **WiFi版** | WiFi 2.4GHz + BLE | 家庭/办公室等有WiFi环境 | 成本优化，标准版 |
| **WiFi+4G版** | WiFi 2.4GHz + BLE + ML307 4G LTE (Cat.4, eSIM) | 户外/移动场景，无WiFi环境 | 信号强度优化，抗干扰设计，功耗<200mA活跃/<10mA休眠 |

**WiFi+4G版技术要求**：采用ML307 4G模块，信号覆盖主流运营商频段，PCB天线隔离设计减少干扰，支持eSIM Profile下载。网络切换逻辑：优先WiFi → WiFi不可用时切换4G → WiFi恢复后切换回WiFi。

### 1.5 数据隐私原则 (Data Privacy Principles)

- **无痕处理**: 所有用户的语音数据仅用于实时处理,不在设备端或云端进行任何形式的存储
- **加密传输**: 数据在传输过程中全程采用TLS/SSL加密,保障通信安全
- **本地化配置**: 仅在设备本地加密存储WiFi凭证等必要的非个人配置信息
- **合规认证**: 符合《个人信息保护法》等相关隐私保护规定

### 1.6 目标用户与使用场景

**主要客户**: 灵犀的毛绒玩具制造商
**最终用户**: 玩具购买者及使用者(全年龄段)

**典型使用场景**:
- 家庭陪伴: 作为日常对话伙伴,进行闲聊、讲故事、知识问答
- 情感互动: 通过语音和动作感知,提供情感回应和陪伴
- 多场景切换: 支持家庭/办公室等多WiFi环境自动切换

## 2. 用户场景与测试

### 用户故事 1 - 基本语音对话交互 (优先级: P1)

用户首次使用AI语音盒子与毛绒玩具进行语音对话。用户按下按钮开机，玩具发出欢迎提示音，用户直接对着玩具说话，玩具能够识别语音并通过内置扬声器回应，实现自然的双向对话交互。

**为什么是此优先级**: 语音对话是产品的核心价值主张，没有此功能产品无法使用。这是最小可行产品(MVP)的基础。

**独立测试**: 可通过开机后直接与玩具对话并接收语音回复来完整测试。交付价值:用户获得与玩具对话的基本体验。

**验收场景**:

1. **Given** 盒子处于关机状态, **When** 用户长按按钮3秒开机, **Then** 盒子播放开机音乐
2. **Given** 盒子已完成网络配置并开机, **When** 开机成功联网后, **Then** 盒子主动播放后台准备的"问候语"(如"你好,很高兴见到你")
3. **Given** 盒子已开机并完成网络配置, **When** 用户说"你好", **Then** 盒子在1.5秒内通过扬声器回应
3. **Given** 用户正在与盒子对话, **When** 用户在盒子说话过程中打断说"等一下", **Then** 盒子立即停止当前语音输出并等待新的用户输入
4. **Given** 盒子正在播放AI回应, **When** 用户摇晃玩具(IMU检测到动作), **Then** 盒子识别动作并在语音回应中提及"我感觉到你在和我玩"

---

### 用户故事 2 - 初次配网设置 (优先级: P2)

用户购买产品后,首次开机需要通过手机APP或小程序为盒子配置WiFi网络连接,使盒子能够访问互联网进行AI对话服务。

**为什么是此优先级**: 虽然是首次使用的必需步骤,但可以通过离线模式(预设对话)实现P1的基本测试。配网是产品正常使用的前提,但不阻碍核心功能演示。

**独立测试**: 可通过全新盒子从开机到成功连接WiFi的完整流程独立测试。交付价值:用户能够自主完成设备联网。

**验收场景**:

1. **Given** 盒子首次开机且未绑定, **When** 开机完成, **Then** 盒子播放提示音"请使用手机APP连接我"并自动进入蓝牙配对模式
2. **Given** 盒子处于蓝牙配对模式, **When** 用户在手机APP中搜索并连接盒子蓝牙, **Then** APP显示"已连接设备"并显示可用WiFi网络列表
3. **Given** APP显示WiFi列表, **When** 用户选择家庭WiFi并输入密码点击连接, **Then** 盒子连接成功并播放提示音"网络连接成功",该WiFi凭证被保存
4. **Given** 盒子已配置1个或多个网络, **When** 盒子断电重启, **Then** 盒子自动扫描并连接已保存的可用WiFi网络(按信号强度优先)无需重新配置
5. **Given** 盒子配网失败(密码错误或信号弱), **When** 连接超时, **Then** 盒子播放提示音"网络连接失败,请重试"并保持蓝牙配对模式
6. **Given** 盒子已保存家庭和公司两个WiFi, **When** 用户带着玩具从家到公司, **Then** 盒子检测到家庭WiFi信号丢失后自动扫描并连接到公司WiFi
7. **Given** 用户需要添加新的WiFi网络, **When** 用户通过APP添加第3个WiFi, **Then** 新WiFi凭证被保存,盒子可存储并管理多个网络(至少支持30个)
8. **Given** 盒子已绑定但所有WiFi不可用, **When** 用户语音或摇晃唤醒盒子, **Then** 盒子播放提示音"网络未连接,请前往小程序配网",不自动进入配网模式
9. **Given** 盒子已绑定但未联网, **When** 用户连续按2次按钮(每次1秒,间隔<2秒), **Then** 盒子播放提示音"正在进入配网模式"并启动蓝牙配对模式

### 用户故事 3 - 电源管理 (优先级: P3)

用户需要管理盒子的电源状态,包括充电提醒、低电量警告、以及正常关机,确保设备使用安全和良好的用户体验。

**为什么是此优先级**: 电源管理是产品可用性的重要保障,但不影响核心对话功能的演示和测试。可以在基本功能验证后再实现完整的电源管理逻辑。

**独立测试**: 可通过模拟不同电量状态(充电中、低电量、关机)独立测试。交付价值:用户能够安全使用和维护设备。

**验收场景**:

1. **Given** 盒子电量低于15%, **When** 电量触发低电警告, **Then** 盒子每隔5分钟播放提示音"电量不足,请充电"
2. **Given** 盒子正在使用, **When** 用户连接充电线, **Then** 盒子播放提示音"开始充电,充电期间请勿使用"并禁用所有对话和动作交互功能
3. **Given** 盒子正在充电, **When** 电量达到100%, **Then** 盒子播放提示音"充电完成"
4. **Given** 盒子处于开机状态, **When** 用户长按按钮5秒, **Then** 盒子播放关机音乐并语音提示"再见,下次见"后关闭电源
5. **Given** 盒子电量低于5%, **When** 电量耗尽, **Then** 盒子播放提示音"电量耗尽,即将关机"后自动关机

---

### 用户故事 4 - 设备重置与恢复 (优先级: P4)

用户在设备出现问题或需要转让设备时,能够通过按钮操作重置设备到出厂状态,清除所有个人配置和数据。

**为什么是此优先级**: 重置功能主要用于故障排除和设备转让场景,使用频率低,不影响日常使用和核心功能。

**独立测试**: 可通过执行重置操作并验证设备恢复到初始状态独立测试。交付价值:用户能够解决配置问题或安全地转让设备。

**验收场景**:

1. **Given** 盒子处于关机状态, **When** 用户长按按钮10秒, **Then** 盒子播放提示音"设备重置中,请稍候"
2. **Given** 重置流程启动, **When** 重置完成, **Then** 盒子清除所有WiFi配置、用户数据,并播放提示音"重置完成,设备已恢复出厂设置"后自动关机
3. **Given** 设备已重置, **When** 用户再次开机, **Then** 盒子表现如同全新设备,提示用户进行配网

---

### 用户故事 5 - 动作识别交互增强 (优先级: P5)

用户在与玩具对话时,通过摇晃、翻转、轻拍等物理动作与玩具互动,盒子通过IMU传感器识别这些动作,并在AI对话中做出相应反应,增强互动趣味性。

**为什么是此优先级**: 动作识别是锦上添花的增强功能,能显著提升用户体验和产品差异化,但不是基本对话功能所必需。

**独立测试**: 可通过执行特定动作(摇晃、翻转、轻拍)并验证AI回应是否包含动作相关内容独立测试。交付价值:用户获得更丰富、更有趣的互动体验。

**验收场景**:

1. **Given** 盒子处于对话模式, **When** 用户快速摇晃玩具3次, **Then** 盒子识别为"摇晃"动作并在对话中回应"哇,你在摇我,好好玩!"
2. **Given** 盒子处于对话模式, **When** 用户将玩具翻转180度(倒置), **Then** 盒子识别为"翻转"动作并回应"呀,我被翻过来了,好晕呀"
3. **Given** 盒子处于对话模式, **When** 用户轻拍玩具2次, **Then** 盒子识别为"轻拍"动作并回应"你在拍我吗?再来一次!"
4. **Given** 盒子处于空闲状态超过5分钟, **When** 用户拿起玩具(IMU检测到移动), **Then** 盒子主动语音问候"你回来啦,我们聊聊吧"

---

### 用户故事 6 - 动作唤醒交互 (优先级: P3)

用户在玩具处于休眠状态时,通过拿起或摇晃等动作直接唤醒设备,并立即开始互动,获得一种"即拿即玩"的无缝体验,无需寻找并按下小按钮。

**为什么是此优先级**: 这是提升产品"生命感"和易用性的重要功能,降低了交互门槛,增强了产品的主动性和灵性,但不影响核心对话流程的实现。

**独立测试**: 可通过将设备置于休眠状态,然后执行"拿起"动作,验证设备是否能被唤醒并主动问候。交付价值:降低了用户的交互门槛,增强了产品的灵性和主动性。

**验收场景**:

1. **Given** 盒子已联网并进入休眠状态, **When** 用户拿起玩具(IMU检测到持续位移), **Then** 盒子在2秒内被唤醒并主动播放问候语,如"你回来啦,我们聊聊吧!"
2. **Given** 盒子未联网并进入休眠状态, **When** 用户拿起玩具, **Then** 盒子被唤醒,并播放配网提示音"请使用手机APP连接我",同时进入蓝牙配对模式
3. **Given** 盒子处于休眠状态, **When** 用户摇晃玩具(快速摇晃≥2次), **Then** 盒子被唤醒,效果等同于"拿起"动作唤醒
4. **Given** 盒子通过动作唤醒后已联网, **When** 唤醒完成, **Then** 盒子自动重连WiFi并恢复到待机状态,准备接收语音输入

---

### 用户故事 7 - OTA固件升级 (优先级: P3)

用户需要为设备升级固件以获取新功能、性能优化和安全补丁,通过OTA(空中升级)方式无需拆机或连接电脑,实现便捷、安全的固件迭代。

**为什么是此优先级**: OTA升级是设备持续优化的基础能力,虽然不是首次使用必需,但对产品长期迭代和问题修复至关重要,支持灰度发布可降低升级风险。

**独立测试**: 可通过模拟云端推送固件更新,测试设备自动检测、下载、安装、回滚等完整流程。交付价值:设备可持续迭代优化,降低维护成本。

**验收场景**:

1. **Given** 盒子已联网且电量≥50%, **When** 云端发布新版本固件(设备在5%灰度范围内), **Then** 设备自动检测到更新并播放提示音"发现新版本固件,是否升级?",APP推送通知
2. **Given** 设备检测到固件更新且用户确认升级, **When** 开始下载固件, **Then** 设备通过HTTPS下载固件到非活动分区,实时上报进度(0%-100%),LED呼吸灯闪烁
3. **Given** 固件正在下载(进度50%), **When** 网络中断, **Then** 设备暂停下载,网络恢复后从50%位置断点续传,无需重新下载
4. **Given** 固件下载完成, **When** 设备校验SHA256和签名, **Then** 校验通过后播放"固件升级中,请勿断电"并开始写入Flash,禁用所有交互功能
5. **Given** 固件写入完成, **When** 设备重启, **Then** 启动新固件,上报版本号到云端,播放"固件升级成功,当前版本:vX.X.X",WiFi凭证等配置100%保留
6. **Given** 新固件启动失败(连续3次重启失败), **When** 检测到启动异常, **Then** 自动回滚到旧版本固件,播放"升级失败已回滚",上报云端并通过APP通知用户
7. **Given** 设备电量<30%, **When** 检测到固件更新, **Then** 设备拒绝升级并播放"电量不足,请充电后再升级"
8. **Given** 设备不在当前灰度范围(如95%设备未被选中), **When** 设备请求升级, **Then** 云端返回"暂无可用更新",设备继续使用当前版本
9. **Given** 用户通过APP主动触发升级检查, **When** 云端有新版本且设备符合条件, **Then** 立即开始升级流程,无需等待24小时自动检测
10. **Given** 云端停止灰度发布(紧急停止), **When** 设备请求升级, **Then** 云端返回"暂无可用更新",已下载未安装的设备不执行升级

### 2.6 边界情况与异常处理

| 场景 | 系统行为 |
|------|----------|
| 用户持续打断(连续3次以上) | 正常响应每次打断,不做特殊处理 |
| WiFi信号丢失或网络中断 | 播放提示音"网络连接失败,请检查网络"并停止对话服务,直到网络恢复 |
| 云端AI服务超时/不可用 | 自动重试1次(总计2次,每次超时2秒),仍失败则播放"服务暂时不可用" |
| 蓝牙配对10分钟无连接 | 自动进入休眠状态,按按钮1秒可唤醒并重新进入配对模式 |
| 充电时电池温度>50°C | 立即停止充电并播放警告"温度过高,已停止充电",降至45°C恢复;连续3次超温则停止充电并关机 |
| 充电期间用户尝试交互 | 播放提示音"充电期间请勿使用",不响应交互请求 |
| WiFi环境切换 | 自动检测信号丢失并扫描连接其他已保存WiFi,切换过程对用户透明 |
| 所有已保存WiFi不可用 | 仅在语音或摇晃唤醒时检测网络状态,若未联网则播放提示音"网络未连接,请前往小程序配网";用户可通过连续按2次按钮(每次按1秒,间隔<2秒)主动进入蓝牙配对模式 |
| 多麦克风输入(环境噪音/多人说话) | 优先处理信号强度最高、最稳定的麦克风输入,过滤远处背景噪音(需波束成形支持) |
| IMU检测剧烈震动(跌落) | 记录事件到日志,继续正常服务(无需暂停或自检) |
| 对话中断后恢复 | AI可主动询问"我刚才讲到一半,你还想继续听吗?"(上下文感知) |

## 3. 功能需求 (Functional Requirements)

### 3.1 硬件交互需求

**硬件交互需求**

- **FR-001**: 盒子必须支持通过单个外置按钮实现以下操作:
  - **开机**: 长按3秒
  - **关机**: 长按5秒
  - **重置**: 关机状态下长按10秒
  - **进入配网模式**: 在开机状态下,连续按2次按钮(每次按1秒,两次按压间隔<2秒),播放提示音"正在进入配网模式"并启动蓝牙配对模式
  - *注: 按钮交互时长(3秒/5秒)待用户体验测试优化,可根据实际使用反馈调整*
- **FR-002**: 盒子必须通过双麦克风阵列实现实时语音输入,支持在播放音频时检测用户打断并立即停止播放(基于乐鑫AEC组件实现,详见技术约束)
- **FR-003**: 盒子必须通过内置扬声器播放AI语音回应、系统提示音、开关机音乐
- **FR-004**: 盒子必须通过IMU传感器实时检测并识别至少以下几种用户动作:拿起、摇晃(区分快速和温柔)、翻转、轻拍、静置、跌落(自由落体)
- **FR-004a (动作定义参考)**: 上述动作的算法具体实现(例如加速度阈值、角速度变化、持续时间等参数)在详细设计阶段,应重点参考Project Magic项目的相关定义与实现,以确保动作识别的准确性和交互体验的自然流畅。跌落动作应触发保护性或安抚性回应(如"哎呀,我摔倒了,你没事吧?")
- **FR-005**: 盒子必须支持通过USB接口进行充电,并在充电状态改变时播放相应提示音
- **FR-005a (LED状态指示)**: 盒子必须通过LED指示灯显示设备状态:
  - 充电中:LED呼吸灯效果(或红色常亮)
  - 充电完成:LED绿色常亮(或熄灭)
  - 充电异常(温度过高):LED红色闪烁
  - 说话状态(AI语音播放中):待定
  - 聆听状态(监听用户输入):待定
  - 待机状态:待定
  - *注: 说话、聆听、待机等工作状态的LED效果(颜色、闪烁模式、呼吸效果等)将在详细设计阶段定义*
- **FR-005b (触摸功能支持)**: 盒子硬件设计必须预留ESP32S3触摸引脚,支持外接铜箔实现触摸交互功能:
  - **引脚预留**: PCB设计必须预留至少2-4路触摸引脚(推荐GPIO1-GPIO14中选择),引脚需引出至可外接铜箔的焊盘或接口
  - **可选功能**: 触摸功能为可选功能,不外接铜箔时不影响盒子基本功能运行
  - **触摸检测**: 当外接铜箔并启用触摸功能时,盒子必须能检测到触摸事件(按下/释放)
  - **灵敏度配置**: 触摸灵敏度阈值应可通过固件配置调节,适配不同铜箔面积和厚度
  - **用途举例**: 可用于实现抚摸互动(如抚摸玩具头部触发温柔回应)、触摸唤醒、触摸控制等扩展交互
  - *注: 具体触摸交互逻辑(动作定义、AI回应方式)在详细设计阶段根据实际应用场景定义*
- **FR-005c (震动反馈支持)**: 盒子必须配备偏心转子振动电机,支持多模态触觉反馈交互:
  - **电机类型**: 偏心转子电机(ERM)或线性谐振驱动器(LRA),推荐ERM(成本低、驱动简单)
  - **驱动方式**: 通过ESP32S3 GPIO引脚驱动,使用PWM信号控制震动强度(占空比0-100%)
  - **震动模式**: 支持可编程震动模式,参数包括:震动时长(ms)、间隔时长(ms)、震动强度(PWM占空比%)
  - **预设模式**: 固件内置至少10种预设震动模式(如短促震动、节奏震动、持续震动等)
  - **电路保护**: 驱动电路需包含限流保护和反向二极管保护
  - **功耗要求**: 震动电机工作电流<100mA @ 3.7V,支持快速启停(响应时间<50ms)
  - *注: 具体震动模式参数在详细设计阶段根据实际测试效果调优*

**网络与连接需求**

- **FR-006**: 盒子必须支持2.4GHz WiFi(802.11 b/g/n)网络连接
- **FR-007**: 盒子的配网与绑定逻辑:
  - **首次开机(未绑定)**: 必须自动进入蓝牙配对模式,广播蓝牙信号供手机APP/小程序连接进行设备绑定
  - **已绑定但WiFi不可用**: 不自动进入配网模式,仅在语音或摇晃唤醒时检测网络状态,若未联网则播放提示音"网络未连接,请前往小程序配网"
  - **手动进入配网模式**: 用户可在任何时候通过连续按2次按钮(每次按1秒,间隔<2秒)主动进入蓝牙配对模式
  - **4G版特殊说明**: WiFi+4G版在首次绑定时可不要求配网,允许先通过4G网络使用,后续再配置WiFi网络
- **FR-008**: 盒子必须在成功配对后,通过蓝牙接收来自手机APP的WiFi凭证(SSID和密码)并尝试连接
- **FR-009**: 盒子必须在WiFi连接成功后播放成功提示音并保存该网络凭证,连接失败后播放失败提示音并保持蓝牙配对模式
- **FR-010**: 盒子必须支持存储多个WiFi网络凭证(至少30个),每个凭证包含SSID、密码(加密存储)、上次连接时间
- **FR-010a**: 盒子在开机或网络断开时必须自动扫描周围WiFi,优先连接已保存网络中信号强度最强的可用网络
- **FR-010b**: 盒子在当前WiFi信号丢失时,必须自动扫描并尝试连接其他已保存的可用WiFi网络,无需用户干预
- **FR-010c**: 盒子必须支持通过APP管理已保存的WiFi网络,包括添加新网络、删除已保存网络、查看已保存网络列表

**语音交互需求**

- **FR-011**: 盒子必须能够采集用户语音输入并通过网络传输至云端ASR服务进行语音识别,将识别结果(文本)用于AI处理
- **FR-012**: 盒子必须能够接收云端TTS服务生成的语音数据并通过扬声器播放
- **FR-013**: 盒子必须支持两种打断模式:
  - **模式1-关键词打断**: 当用户说出特定关键词(如"等一下""停一下""暂停")时,盒子立即停止播放并等待新输入
  - **模式2-语音检测打断**: 只要双麦克风检测到用户开始说话(基于AEC处理后的语音能量检测),盒子立即停止播放
- **FR-013a**: 打断模式可通过云端配置选择,默认使用模式2(语音检测打断),响应时间≤500ms
- **FR-014**: 盒子必须在检测到用户动作(通过IMU)时,将动作信息作为上下文传递给AI,使AI回应能够关联用户动作
- **FR-015**: 盒子必须在网络连接正常时提供完整的在线AI对话服务
- **FR-015a**: 盒子在网络未连接或中断时,必须播放提示音"网络未连接,请先配置网络"或"网络连接失败,请检查网络",不提供对话服务
- **FR-015b**: 盒子在云端AI服务请求失败或超时(超时阈值2秒)时,必须自动重试1次,若仍失败则播放提示音"服务暂时不可用,请稍后再试"

**音频提示需求**

- **FR-016**: 盒子必须内置以下系统提示音:开机音乐、关机音乐、网络连接成功、网络连接失败、网络未连接请前往小程序配网、正在进入配网模式、开始充电(含充电期间请勿使用提示)、充电完成、电量不足、电量不足请充电后再升级、电量耗尽、温度过高已停止充电、网络延迟过高请稍后再试、设备重置中、重置完成、请使用手机APP连接、服务暂时不可用、发现新版本固件是否升级、固件升级中请勿断电、固件升级成功、升级失败请重试、升级失败已回滚
- **FR-017**: 盒子必须在特定系统事件触发时自动播放对应提示音(如开机时播放开机音乐)
- **FR-018**: 盒子必须确保系统提示音优先级高于AI语音播放,在播放提示音时暂停AI语音

**电源管理需求**

- **FR-019**: 盒子必须在电量低于15%时每隔5分钟播放一次低电量提示音
- **FR-020**: 盒子必须在电量低于5%时播放电量耗尽提示音并自动关机
- **FR-021**: 盒子必须在连接充电器时播放充电提示音"开始充电,充电期间请勿使用",断开充电器时停止充电指示
- **FR-022**: 盒子必须在充电完成(电量达100%)时播放充电完成提示音
- **FR-022a**: 盒子在充电状态下必须禁用所有交互功能(语音对话、按钮操作除外、IMU动作识别),仅允许断开充电器或长按5秒关机
- **FR-022b (温度监测与保护)**: 盒子必须在充电过程中持续监测电池温度(采样频率≥1次/秒),当温度超过50°C时立即停止充电(2秒内完成保护动作)并播放警告提示音"温度过高,已停止充电",温度降至45°C以下时自动恢复充电
  - **温度阈值设定依据**: 基于Li-ion电池安全标准和ESP32实际应用经验:
    - Li-ion电池安全充电温度范围: 0°C ~ 45°C (推荐), 最高不超过50°C
    - 业界标准: 多数充电器禁止在50°C以上充电,60°C为锂电池安全运行极限
    - 消费电子产品实践: ESP32系统可工作至85°C,电池在50°C以下充电仍在安全范围内
    - 5°C滞环设计(50°C停止/45°C恢复)可有效防止温度在阈值附近波动导致的频繁开关充电
    - AI玩具使用场景: 考虑到可能在较温暖的环境中使用(如夏季室内),50°C阈值比45°C更实用,减少误触发
  - **保护响应时间**: 检测到温度>50°C后2秒内必须断开充电电路
  - **恢复条件**: 温度持续低于45°C超过30秒后方可恢复充电,避免温度刚降下又快速回升
- **FR-022c (极端过温保护)**: 盒子在充电温度异常(连续3次超温保护,即3次达到>50°C)时必须停止充电并保持关机状态,LED红色快速闪烁(2Hz)5秒后熄灭,需要用户拔出充电线等待冷却
  - **连续超温判定**: 在单次充电周期内,累计触发3次温度>50°C保护,且每次间隔<10分钟,判定为电池或环境异常
  - **安全关机**: 播放提示音"充电异常,设备将关机,请联系客服"后自动关机
  - **恢复方式**: 必须断开充电线并等待至少30分钟冷却后,重新插入充电线才能尝试再次充电
- **FR-023**: 盒子必须在任何状态下(包括蓝牙配对模式、待机、对话空闲)连续10分钟无用户交互(无语音输入、无按钮操作、无IMU动作)时自动进入休眠状态
- **FR-024**: 盒子在休眠状态下必须关闭蓝牙广播、WiFi连接、麦克风监听,仅保持按钮唤醒和IMU动作唤醒功能(低功耗IMU监听模式)
  - *注: WiFi断开的省电效果需实测验证,若WiFi保持连接功耗增加不显著,可优化为保持WiFi连接以加快唤醒响应*
- **FR-025**: 用户在休眠状态下按按钮1秒必须唤醒盒子
- **FR-025a (动作唤醒)**: 在休眠状态下,当IMU检测到指定的唤醒动作(定义为"拿起"或"快速摇晃")时,设备也必须自动唤醒,其效果等同于按钮唤醒
- **FR-025b (唤醒后行为)**: 无论是通过按钮还是动作唤醒,设备恢复到休眠前的状态。具体行为如下:
  - **已绑定且已配网**: 重连WiFi(或4G)并进入待机状态;若网络连接成功,应主动发起问候语音(如"你回来啦,我们聊聊吧!")
  - **已绑定但未联网**: 播放提示音"网络未连接,请前往小程序配网",不自动进入配网模式(用户可通过连按2次按钮手动进入)
  - **未绑定**: 进入蓝牙配对模式,播放提示音"请使用手机APP连接"

**设备管理需求**

- **FR-026**: 盒子必须支持恢复出厂设置操作,清除所有保存的WiFi凭证(包括多个已保存网络)、用户配置和缓存数据
- **FR-027**: 盒子必须在重置完成后自动关机,下次开机时表现为全新设备状态
- **FR-028**: 盒子必须在重置过程中播放重置提示音,重置完成后播放完成提示音

**数据隐私需求**

- **FR-029**: 盒子必须通过加密连接(TLS/SSL)将语音数据实时传输到云端AI服务
- **FR-030**: 盒子本地不得存储任何用户语音数据(音频文件或转写文本)
- **FR-031**: 盒子重置操作必须清除所有可能包含用户信息的缓存数据(不包括固件和系统提示音)

**存储管理需求**

- **FR-033**: 盒子本地仅存储必要的系统数据:固件、系统提示音、多个WiFi凭证(加密存储,至少30个)、设备状态
- **FR-034**: 盒子不得存储对话历史、用户行为日志、或任何可累积增长的用户数据
- **FR-035**: 盒子的日志功能(如有)必须采用循环日志机制,日志文件总大小不得超过100KB,自动覆盖最旧记录
- **FR-036**: 盒子在存储WiFi凭证达到上限(10个)时,必须支持通过APP删除旧网络后添加新网络,或自动覆盖最久未使用的网络

### 3.2 多模态反馈交互增强需求

**设计理念**: 通过预设音效和震动反馈增强设备"生命感",在未被语音或晃动唤醒时提供主动反馈,无论在线或离线状态都能保持基本交互体验。

- **FR-037**: 盒子在检测到IMU动作时(如轻拍、温柔摇晃、翻转等),若当前未被语音唤醒或晃动唤醒,则必须播放预设的非语言音效(如好奇的"嗯?"、开心的哼唱)并触发对应的震动反馈,而非保持沉默
  - **触发条件**: 不限于离线状态,在线状态下若未被语音/晃动唤醒也应触发此反馈
  - **震动反馈**: 结合音效播放对应震动模式(如轻拍触发短促震动,摇晃触发节奏震动)
  - **硬件要求**: 盒子必须配备偏心转子振动电机(ERM或LRA),通过GPIO驱动,支持震动强度(PWM占空比)和模式(震动时长、间隔)控制
- **FR-038**: 盒子必须支持为不同玩具角色配置专属音效库和震动模式库(如"小熊"角色摇晃时发出笑声+温柔震动,"机器人"角色发出机械音效+节奏震动)
- **FR-039**: 盒子被拿起时(检测到"拿起"动作),若未被语音/晃动唤醒,应播放简短的问候音效并配合轻微震动,而非完全无响应
  - **区别于FR-025a**: FR-025a针对休眠状态的唤醒,本条针对待机状态的主动反馈
- **FR-040**: 预设音效和震动反馈的优先级应低于系统提示音和AI语音,但高于沉默状态
  - **存储要求**: 总音效数量≤10个,Flash占用<500KB
  - **震动模式**: 预设震动模式≤10种,存储占用<10KB(模式参数:震动时长、间隔、强度)

### 3.3 多语言支持需求

**设计理念**: 支持中英文系统提示语音,通过云端配置或固件配置灵活选择语言版本,满足国内外不同市场需求。

- **FR-045**: 盒子必须支持中文和英文两种语言的系统提示音,包括所有FR-016定义的提示音类型(开机音乐、关机音乐、网络连接成功/失败、充电相关、电量提示、设备重置等)
- **FR-046**: 盒子必须在固件烧录阶段通过menuconfig配置默认语言版本(中文版/海外版),烧录后系统提示音默认使用对应语言
- **FR-047**: 盒子必须支持通过云端配置动态切换系统提示音语言,云端可针对特定批次设备标识目标市场(如"海外市场"),设备联网后自动下载并切换至对应语言的提示音
- **FR-048**: 云端语言配置优先级高于固件默认配置,即:若云端配置了语言版本,设备联网后自动应用云端配置;若云端未配置,则使用固件默认语言
- **FR-049**: 系统提示音语音包必须支持热更新,设备联网后可从云端下载新语言包并替换本地提示音,无需重新烧录固件
- **FR-050**: 语音包文件必须采用OGG格式Opus封装,每种语言的完整语音包大小≤1MB,支持中英文两种语言时总占用≤2MB

**实现说明**:
- 固件menuconfig提供语言选项: `CONFIG_LANG_CN`(中文版) / `CONFIG_LANG_EN`(海外英文版)
- 云端通过设备配置API下发语言标识,设备在联网时查询并应用
- 语音包存储在Flash独立分区,支持动态替换

### 3.4 上下文感知与交互优化需求 (云端)

**设计理念**: 通过上下文记忆和环境感知,让交互更智能、更自然。

- **FR-041**: 盒子在AI回应被用户打断后,将打断事件信息发送至云端,由云端AI决定是否主动询问"我刚才讲到一半,你还想继续听吗?"
- **FR-042**: 盒子应支持连续动作识别(如连续轻拍3次触发彩蛋,摇晃+翻转识别为组合动作),并给予特殊反馈
- **FR-043**: 盒子在深夜时段(0:00-6:00,需从云端获取时间戳)被唤醒时,将时段信息发送至云端,由云端AI生成更温柔的问候语(如"这么晚还没睡吗?")
- **FR-044**: 对话上下文记忆由云端AI服务处理,盒子不保存对话历史

### 3.5 OTA固件升级需求

**设计理念**: 支持安全、可靠的空中固件升级,通过灰度发布降低升级风险,确保设备可持续迭代优化。

- **FR-051**: 盒子必须支持OTA(Over-The-Air)固件升级功能,采用ESP-IDF原生OTA方案:
  - **双分区方案**: Flash划分为ota_0和ota_1两个应用分区,支持A/B分区切换
  - **升级触发**: 设备定期(每24小时)向云端查询固件更新,或用户通过APP主动触发升级检查
  - **版本校验**: 云端返回固件版本号、文件大小、MD5/SHA256校验和,设备对比本地版本判断是否需要升级
  - **下载方式**: 通过HTTPS从云端下载固件到非活动分区(ota_0或ota_1)
  - **断点续传**: 支持固件下载断点续传,网络中断后可从上次下载位置继续,避免重复下载
- **FR-052**: 盒子必须支持**灰度发布**机制,由云端控制升级策略:
  - **设备分组**: 云端根据设备ID、固件版本、地域等维度将设备分组
  - **灰度比例**: 云端配置灰度升级比例(如5% → 20% → 50% → 100%),设备请求升级时,云端根据比例决定是否下发升级包
  - **灰度标识**: 设备上报唯一标识(MAC地址或设备ID),云端根据哈希算法或白名单判断设备是否在灰度范围内
  - **升级控制**: 若设备不在当前灰度范围,云端返回"暂无可用更新",设备继续使用当前版本
  - **紧急停止**: 云端可随时停止灰度发布,已下载未安装的设备不执行升级
- **FR-053**: 盒子在执行OTA升级时必须保证安全性和用户体验:
  - **电量检查**: 升级前检查电量,电量<30%时拒绝升级并提示"电量不足,请充电后再升级"
  - **充电状态**: 允许在充电状态下升级(优先场景),非充电状态电量≥50%时也允许升级
  - **用户确认**: 检测到新版本后,播放提示音"发现新版本固件,是否升级?"并通过APP通知用户,等待用户确认(或支持静默升级配置)
  - **静默升级**: 云端可配置静默升级策略(在休眠状态且充电时自动升级),无需用户确认
  - **升级中提示**: 升级过程中LED呼吸灯闪烁,禁用所有交互功能(语音、按钮、IMU),播放提示音"固件升级中,请勿断电"
  - **进度上报**: 升级进度(0%-100%)实时上报云端,可在APP端显示
- **FR-054**: 盒子必须支持升级失败后的回滚机制:
  - **校验失败**: 固件下载完成后,验证MD5/SHA256校验和,不匹配则删除固件并提示"升级失败,请重试"
  - **启动失败**: 新固件启动失败(连续3次重启失败),自动回滚到旧版本固件
  - **回滚通知**: 回滚成功后,设备上报云端并通过APP通知用户"升级失败已回滚,当前版本:vX.X.X"
  - **版本标记**: 云端标记失败的固件版本,暂停对该设备的后续升级推送
- **FR-055**: 盒子在升级成功后必须执行以下操作:
  - **版本上报**: 重启后上报新版本号到云端,更新设备版本记录
  - **用户通知**: 播放提示音"固件升级成功,当前版本:vX.X.X",并通过APP推送通知
  - **配置保留**: 升级过程不影响WiFi凭证、用户配置、语言设置等NVS数据
  - **日志记录**: 记录升级时间、旧版本号、新版本号到循环日志
- **FR-056**: OTA升级过程必须遵循以下安全要求:
  - **固件签名**: 固件包必须包含数字签名,设备验证签名有效性后才执行升级(防止固件篡改)
  - **HTTPS传输**: 固件下载必须通过HTTPS加密传输,验证服务器证书
  - **防回滚**: 禁止降级到低于最低安全版本的固件(云端配置最低版本号)
  - **完整性校验**: 使用SHA256校验固件完整性,校验失败立即停止升级

**实现说明**:
- 采用ESP-IDF esp_https_ota组件
- OTA分区配置: ota_0 (3MB) + ota_1 (3MB) + otadata (8KB)
- 云端API: `/api/ota/check`(检查更新) + `/api/ota/download`(下载固件)
- 支持chunked下载,每次下载4KB-8KB数据块

### 3.6 关键实体

- **语音会话**: 表示一次完整的用户与AI的对话交互,包含动作上下文、时间戳等属性(注:不包含语音数据本身,语音数据实时处理后立即丢弃;不保存历史记录)
- **网络配置**: 存储多个WiFi网络凭证(至少10个),每个包含SSID、密码(加密存储)、上次连接时间、信号强度等属性,持久化保存在设备本地
- **设备状态**: 表示盒子当前的运行状态,包含电量百分比、网络连接状态、蓝牙配对状态、充电状态、音频播放状态、温度状态等属性,运行时状态不持久化。设备状态需要上报云端,后续在APP端显示
- **用户动作**: 表示IMU传感器检测到的用户物理交互,包含动作类型(摇晃/翻转/轻拍/静置)、动作强度、时间戳等属性,实时传递给AI后不保存
- **系统提示音**: 预置的音频文件资源,包含提示音类型、音频文件路径、播放优先级等属性,固化在固件中
- **预设音效**: 用于多模态反馈的非语言音效文件(如"嗯?"、哼唱等),包含音效类型、文件路径、触发条件等属性,固化在固件中,总数≤10个
- **震动模式**: 预设的震动反馈模式参数,包含模式ID、震动时长(ms)、间隔时长(ms)、震动强度(PWM占空比%)等属性,固化在固件中,总数≤10种
- **OTA固件包**: 用于设备升级的固件二进制文件,包含版本号、文件大小、校验和(SHA256)、数字签名、下载URL等属性,存储在云端,由灰度发布策略控制下发
- **循环日志**: (可选)用于故障诊断的临时日志,固定大小100KB,采用循环覆盖机制,不保存用户隐私数据,包含OTA升级记录(升级时间、版本变化、成功/失败状态)

## 4. 非功能性需求 (Non-Functional Requirements)

本章节整合所有性能、可靠性、安全性和易用性相关的量化指标,为测试和运维团队提供明确的质量评估标准。

### 4.1 性能需求 (Performance)

**NFR-001 语音交互响应时间**
- **指标**: 用户说话结束到AI开始播放回应的端到端延迟 ≤ 2秒
- **测试条件**: 正常网络环境(延迟<100ms,丢包率<1%),WiFi信号≥-70dBm
- **降级策略**: 若网络延迟>200ms,允许延迟增至3秒;若延迟>5秒,直接放弃本次请求并播放提示音"网络延迟过高,请稍后再试"
- **关联需求**: SC-002, FR-015

**NFR-002 打断检测响应时间**
- **指标**: 检测到用户打断到停止播放的响应时间 ≤ 500毫秒
- **测试条件**: 双麦克风波束成形正常工作,环境噪音<60dB
- **技术实现**: 双麦克风阵列实时检测语音能量峰值,触发播放中断
- **关联需求**: SC-003, FR-013

**NFR-003 WiFi自动切换速度**
- **指标**: 当前WiFi信号丢失后,30秒内自动连接其他已保存网络
- **测试条件**: 至少保存2个可用WiFi,备用WiFi信号≥-75dBm
- **降级策略**: 若所有已保存WiFi不可用,仅在语音或摇晃唤醒时播放提示音"网络未连接,请前往小程序配网";用户可通过连续按2次按钮手动进入配网模式
- **关联需求**: SC-005a, FR-010b, FR-007

**NFR-004 休眠与唤醒性能**
- **休眠触发**: 连续10分钟无交互自动进入休眠状态
- **休眠功耗**: 休眠功耗 ≤ 待机功耗的10% (目标<10mA)
- **唤醒速度**: 从休眠到可用状态 ≤ 2秒 (包含WiFi重连)
- **关联需求**: SC-009, FR-023, FR-024, FR-025

**NFR-005 IMU动作识别准确率**
- **指标**: 针对摇晃、翻转、轻拍三种主要动作,识别准确率 ≥ 85%
- **测试方法**: 每种动作重复测试20次,准确识别次数/总次数
- **误识别容忍**: 静置状态下误触发率 < 5% (避免无动作时频繁误识别)
- **关联需求**: SC-004, FR-004

**NFR-006 系统提示音及时性**
- **指标**: 系统事件触发后1秒内开始播放对应提示音
- **覆盖场景**: 开机/关机/充电/网络连接/电量警告等13种提示音
- **优先级**: 系统提示音优先级高于AI语音,播放时暂停AI输出
- **关联需求**: SC-008, FR-017, FR-018

### 4.2 可靠性需求 (Reliability)

**NFR-007 WiFi连接成功率**
- **指标**: WiFi信号强度≥-70dBm时,连接成功率 ≥ 95%
- **测试样本**: 100次连接尝试(包含开机、切换网络等场景)
- **失败处理**: 连接失败播放提示音,保持蓝牙配对模式等待用户干预
- **关联需求**: SC-005, FR-009

**NFR-008 云端服务容错**
- **超时阈值**: 单次API请求超时阈值设为2秒
- **重试策略**: 请求失败或超时自动重试1次(总计2次尝试)
- **降级提示**: 重试后仍失败,播放"服务暂时不可用,请稍后再试"
- **关联需求**: FR-015b

**NFR-009 充电安全与保护**
- **温度监测**: 充电时实时监测电池温度,采样频率≥1次/秒
- **过温保护**: 温度>50°C立即停止充电(2秒内)并播放警告"温度过高,已停止充电",降至45°C自动恢复(需持续30秒以上)
- **滞环设计**: 5°C滞环(50°C停止/45°C恢复)防止频繁开关充电
- **多次超温**: 单次充电周期内连续3次超温保护触发(每次间隔<10分钟)后,停止充电并关机,需用户拔线冷却至少30分钟
- **阈值依据**: 基于Li-ion电池安全标准(推荐0-45°C,最高50°C)和ESP32实际应用经验,50°C阈值适合AI玩具使用场景
- **关联需求**: FR-022b, FR-022c

**NFR-010 多WiFi管理可靠性**
- **存储容量**: 至少支持保存10个WiFi网络凭证,超过上限时自动覆盖最久未使用的网络
- **自动选择**: 开机/断网时,优先连接信号最强的已保存网络
- **覆盖策略**: 达到上限时,支持APP删除旧网络或自动覆盖最久未使用网络(需用户确认)
- **关联需求**: FR-010, FR-010a, FR-036

**NFR-010a WiFi信号可靠性与抗干扰测试**
- **信号强度稳定性测试**:
  - **测试条件**: WiFi信号强度在-70dBm至-50dBm范围内波动
  - **连接稳定性**: 连续运行30分钟,连接保持率≥99% (允许1次短暂断连并自动恢复)
  - **测试样本**: 每个信号强度等级(-70dBm, -60dBm, -50dBm)测试10次
- **抗干扰能力测试**:
  - **2.4GHz同频干扰**: 在有5个以上邻近WiFi网络(同2.4GHz频段)的环境下,连接成功率≥90%
  - **蓝牙共存干扰**: WiFi和BLE同时工作时(如配网过程),WiFi吞吐量下降<20%,BLE配对成功率≥95%
  - **微波炉干扰**: 在微波炉工作(2.45GHz强干扰源,距离2米)时,WiFi连接保持率≥80%,若断开需在10秒内自动重连
  - **4G共存干扰**(仅WiFi+4G版): WiFi和4G同时工作时,WiFi吞吐量下降<15%,4G信号强度下降<3dBm
- **远距离性能测试**:
  - **测试条件**: 设备与WiFi路由器之间有2堵墙(砖墙/混凝土墙)
  - **信号衰减**: 信号强度≥-75dBm时仍能保持稳定连接
  - **连接成功率**: ≥85% (10次测试中至少8次成功连接并保持稳定)
- **快速重连测试**:
  - **测试场景**: 设备从WiFi覆盖区移出再移入(模拟用户携带设备移动)
  - **重连时间**: 检测到WiFi信号恢复后5秒内完成重连
- **关联需求**: SC-005, NFR-007, FR-010b

**NFR-010b 蓝牙信号可靠性与抗干扰测试**
- **配对成功率测试**:
  - **测试条件**: 设备与手机距离1-10米,无明显障碍物
  - **配对成功率**: ≥98% (100次配对尝试中至少98次成功)
  - **配对时间**: 从搜索到配对成功≤15秒
- **抗干扰能力测试**:
  - **WiFi共存干扰**: BLE配对过程中WiFi扫描同时进行,配对成功率≥95%
  - **多蓝牙设备干扰**: 周围有5个以上活跃蓝牙设备(如手机、耳机、音箱),配对成功率≥90%
  - **2.4GHz频段拥挤**: 在WiFi密集环境(10个以上AP),BLE配对成功率≥85%
- **有效距离测试**:
  - **无障碍物**: 10米距离内配对成功率≥95%
  - **一堵墙障碍**: 5米距离内配对成功率≥90%
  - **信号衰减容忍**: RSSI低至-80dBm时仍能保持配对连接
- **数据传输可靠性**:
  - **WiFi凭证传输**: 在配对成功后,WiFi凭证传输成功率≥99%
  - **传输时间**: 单个WiFi凭证传输完成≤2秒
  - **错误重传**: 传输失败时自动重传,最多3次重试
- **关联需求**: FR-007, FR-008, FR-009

**NFR-010c 4G信号可靠性与抗干扰测试** (仅WiFi+4G版)
- **信号强度与连接稳定性**:
  - **测试条件**: 4G信号强度RSSI在-100dBm至-70dBm范围内
  - **连接稳定性**:
    - RSSI ≥ -90dBm: 连接保持率≥99%,数据传输成功率≥98%
    - RSSI在-100dBm至-90dBm: 连接保持率≥85%,数据传输成功率≥90%
  - **网络切换延迟**: 4G网络在不同基站间切换(小区切换),切换时间<3秒,语音数据包丢失率<5%
- **抗干扰能力测试**:
  - **WiFi/BLE共存**: 4G、WiFi、BLE三模同时工作时:
    - 4G吞吐量下降<10%
    - WiFi吞吐量下降<15%
    - BLE配对成功率≥95%
  - **天线隔离要求**: PCB设计需保证4G天线与WiFi/BLE天线隔离度≥20dB,减少互相干扰
  - **金属屏蔽干扰**: 设备放置在金属桌面或靠近金属物体时,4G信号强度下降<5dBm
- **弱信号性能测试**:
  - **测试场景**: 室内深处、地下室、电梯等弱信号环境
  - **最低可用信号**: RSSI ≥ -105dBm时仍能建立连接(可能限速)
  - **数据传输**: RSSI在-100dBm时,上行语音数据传输成功率≥85%
- **网络切换逻辑测试**:
  - **WiFi优先**: WiFi可用时(信号≥-75dBm),优先使用WiFi,4G保持休眠(<10mA)
  - **4G切换**: WiFi不可用时,5秒内切换至4G并建立连接
  - **WiFi恢复**: WiFi信号恢复后,30秒内切换回WiFi
  - **切换无感知**: 网络切换过程对用户透明,不播放提示音(除非两者都不可用)
- **eSIM管理**:
  - **Profile下载**: 支持OTA下载eSIM Profile,下载成功率≥95%
  - **多Profile管理**: 支持存储≥2个eSIM Profile,切换时间<10秒
- **功耗要求**:
  - **活跃状态**: 4G数据传输时功耗<200mA @ 3.7V
  - **休眠状态**: 4G模块休眠(WiFi可用时)功耗<10mA @ 3.7V
  - **待机状态**: 4G已连接但无数据传输时功耗<50mA @ 3.7V
- **关联需求**: 1.4硬件版本规划, NFR-010a

**NFR-010d OTA固件升级可靠性与安全性**
- **升级成功率测试**:
  - **测试条件**: WiFi信号强度≥-70dBm,电量≥50%,网络延迟<200ms
  - **升级成功率**: ≥98% (100次OTA升级测试中至少98次成功)
  - **回滚成功率**: 升级失败时,回滚成功率≥99%
  - **测试样本**: 涵盖不同网络环境(WiFi/4G)、不同电量状态(50%-100%)、不同固件大小(2MB-4MB)
- **灰度发布控制测试**:
  - **灰度精度**: 云端配置5%灰度比例时,实际升级设备数量误差<±2% (如1000台设备,实际升级数量在30-70台之间)
  - **灰度响应**: 设备请求升级后,云端根据灰度策略决定是否下发,响应时间<2秒
  - **紧急停止**: 云端停止灰度发布后,新请求设备不再收到升级包,停止生效时间<1分钟
  - **白名单优先**: 白名单设备无论灰度比例如何,始终能收到升级包
- **断点续传测试**:
  - **测试场景**: 固件下载过程中人为断网,恢复网络后继续下载
  - **续传成功率**: ≥95% (20次断点续传测试中至少19次成功)
  - **续传位置精度**: 续传起始位置误差<1KB (避免重复下载过多数据)
  - **超时重试**: 下载超时(30秒)后自动重试,最多重试3次
- **升级过程安全性**:
  - **电量保护**: 电量<30%时拒绝升级,电量<20%且正在升级时立即暂停并提示充电
  - **充电优先**: 充电状态下允许升级,升级过程中断开充电线则暂停升级并提示"请保持充电"
  - **防断电保护**: 升级过程中检测到电量低于15%,立即中止升级并回滚,播放"电量不足,升级已取消"
- **固件校验测试**:
  - **SHA256校验**: 固件下载完成后必须校验SHA256,不匹配则删除固件,校验失败率<1%
  - **签名验证**: 固件签名验证失败率<0.1% (1000次测试中最多1次失败,通常因固件损坏)
  - **防篡改**: 手动修改已下载固件文件,设备能检测并拒绝安装,检测成功率100%
- **升级性能测试**:
  - **下载速度**: WiFi环境下,固件下载速度≥200KB/s (3MB固件<15秒下载完成)
  - **安装时间**: 固件写入Flash并重启时间<30秒 (3MB固件)
  - **整体升级时间**: 从开始下载到重启完成<2分钟 (3MB固件,WiFi环境)
- **并发升级测试** (云端压力):
  - **并发能力**: 云端支持≥1000台设备同时请求升级,响应时间<5秒
  - **带宽优化**: 云端支持CDN分发,单台服务器带宽占用<100Mbps (50台设备并发下载)
- **配置保留测试**:
  - **NVS数据**: 升级前后WiFi凭证(至少30个)、用户配置、语言设置等NVS数据100%保留
  - **语音包**: 升级前后系统提示音、预设音效100%保留(除非新版本更新了音效)
  - **用户数据**: 升级不影响任何用户数据(本产品无持久化用户数据,仅验证配置保留)
- **关联需求**: FR-051至FR-056

### 4.3 安全性需求 (Security)

**NFR-011 数据传输加密**
- **加密协议**: 所有网络通信必须使用TLS/SSL加密(TLS 1.2+)
- **证书验证**: 云端API通信需验证服务器证书,防止中间人攻击
- **覆盖范围**: 语音数据上传、AI回应下载、配置同步等所有网络交互
- **关联需求**: FR-029

**NFR-012 零用户数据存储**
- **设备端**: 不存储任何用户语音数据(音频文件或转写文本)
- **云端**: 语音数据处理完成后立即删除,不保留任何记录或日志
- **审计要求**: 可通过代码审计和网络流量监控验证合规性
- **关联需求**: FR-030, FR-031, 数据隐私原则(1.4)

**NFR-013 WiFi凭证保护**
- **加密存储**: WiFi密码使用AES-256加密后存储于NVS分区
- **访问控制**: 仅授权固件模块可访问加密凭证,禁止外部读取
- **重置清除**: 恢复出厂设置时完全清除所有加密凭证
- **关联需求**: FR-026, FR-032

**NFR-014 隐私合规认证**
- **法规遵循**: 符合《中华人民共和国个人信息保护法》等相关法律
- **认证要求**: 产品发布前需通过第三方隐私合规审计
- **数据本地化**: 使用国内AI服务提供商,数据处理不出境
- **关联需求**: 数据隐私原则(1.4), 业务约束

### 4.4 易用性需求 (Usability)

**NFR-015 首次使用体验**
- **指标**: 用户从开机到完成首次语音对话(含配网)总时长 ≤ 3分钟
- **无说明书操作**: 90%的用户能够在无说明书情况下独立完成首次配网
- **引导提示**: 通过系统语音提示引导用户完成开机、配网、首次对话
- **关联需求**: SC-001, SC-007

**NFR-016 续航与电源体验**
- **续航时间**: 中等使用强度(每小时对话10分钟)下,单次充电续航 ≥ 6小时
- **低电量提醒**: 电量<15%时每5分钟播放一次提醒,<5%时自动关机前提醒
- **充电反馈**: 充电状态变化时及时播放提示音(开始充电/充电完成/温度异常)
- **关联需求**: SC-006, FR-019, FR-020, FR-021, FR-022

**NFR-017 交互反馈清晰度**
- **语音提示**: 所有系统事件(开机/关机/充电/网络/错误)均有对应语音提示
- **音效区分**: 成功/失败/警告等不同类型事件使用可区分的音效设计
- **音量适中**: 系统提示音音量适中,不刺耳,符合家庭使用场景
- **关联需求**: FR-016, FR-017, NFR-006

### 4.5 可维护性需求 (Maintainability)

**NFR-018 日志与诊断**
- **循环日志**: 采用固定100KB循环日志,自动覆盖最旧记录
- **隐私保护**: 日志仅包含系统事件和错误信息,不记录用户语音或对话内容
- **故障诊断**: 记录网络连接失败、API超时、传感器异常等关键事件
- **关联需求**: FR-035, 关键实体-循环日志

**NFR-019 设备重置可靠性**
- **完整清除**: 重置操作清除所有WiFi凭证、配置和缓存数据
- **保留固件**: 重置不影响固件和系统提示音资源
- **重置确认**: 重置操作需特定长按时长(10秒),避免误触发
- **关联需求**: FR-026, FR-027, FR-028

### 4.6 硬件约束与技术指标 (Hardware Constraints)

**NFR-020 双麦克风阵列规格**
- **硬件配置**:
  - **ADC芯片**: ES7210 (4通道24位ADC,I2S接口)
  - **麦克风型号**: LMA3729T381-OY3S × 2 (模拟麦克风,兼容MSM381A3729H9BPC封装)
  - **麦克风间距**: 45mm (在乐鑫建议范围4~6.5 cm内,可有效实现声源识别和波束成形)
  - **轴线要求**: 麦克风轴线应平行于水平线
  - **物理隔离**: 麦克风应远离扬声器,与扬声器音腔之间通过橡胶垫等材料隔离缓冲,减少振动干扰
- **音频参数**:
  - **采样率**: 16kHz (ES7210支持8k-96kHz可配置)
  - **位深度**: 24bit (ES7210硬件支持)
  - **频率响应**: 50~16 KHz范围内波动应在 ±3 dB以内
  - **最大声压级**: 麦克风拾音声压 ≤ 102 dB (1KHz)
  - **信噪比**: ≥60dB (确保语音清晰度)
- **算法功能**:
  - **回声消除(AEC)**: 必须基于乐鑫(Espressif)官方AEC组件实现,支持扬声器播放时麦克风回声消除,防止循环反馈,确保打断(Barge-in)功能可靠性
    - **AEC参考信号**: 从DA后级、PA(NS4150B)前级回采
    - **功放THD要求**: 100Hz<10%, 200Hz<6%, 350Hz以上<3%
  - **波束成形**: 利用双麦克风相位差(45mm间距)进行方向性增强,抑制侧向噪音,实现声源识别
  - **噪声抑制**: 环境噪音<60dB时,能有效提取人声信号
  - **打断检测**: 基于AEC处理后的语音能量检测,在扬声器播放期间实时监测用户语音输入
- **详细参考**: 见第9章技术参考文档

**NFR-021 IMU传感器动作定义**

*注: 以下参数为初步定义,详细实现应参考Project Magic项目的经验数据*

- **拿起检测**: 三轴合成加速度从静置状态(<0.2g)突然上升至>0.5g并持续>500ms,识别为拿起动作,用于休眠唤醒或主动问候
- **摇晃检测(快速)**: X/Y轴加速度变化频率>2Hz,振幅>1.0g,持续时间≥1秒,识别为快速摇晃,可用于唤醒或触发兴奋回应
- **摇晃检测(温柔)**: X/Y轴加速度变化频率1-2Hz,振幅0.3-1.0g,持续时间≥2秒,识别为温柔摇晃,触发温和回应
- **翻转检测**: Z轴角度变化≥180°,速率适中(0.5-2秒完成翻转),识别为翻转
- **轻拍检测**: Z轴加速度瞬时峰值>1.5g,出现2次明显峰值(间隔<500ms),识别为轻拍
- **跌落检测**: 三轴合成加速度同时接近0g(自由落体),持续>100ms,识别为跌落,触发安抚性回应
- **静置检测**: 三轴加速度变化<0.1g持续≥30秒,识别为静置
- **组合动作**: 连续识别多个动作(如摇晃+翻转),触发特殊反馈或彩蛋
- **算法参考**: 详细阈值调优和滤波算法应参考Project Magic项目的实现经验

**NFR-022 音频编解码规格**
- **硬件配置**:
  - **Audio Codec芯片**: ES8311 (低功耗立体声音频编解码器,I2S/PCM接口)
  - **DAC性能**: 24位DAC,支持8k-96kHz采样率
  - **ADC性能**: 24位ADC (本项目主要用于参考信号回采)
  - **输出驱动**: 差分输出连接至NS4150B功放
- **软件编码**:
  - **编码格式**: Opus (开源,低延迟,高压缩率)
  - **码率**: 32kbps (语音质量与带宽的平衡点)
  - **采样率**: 16kHz单声道
  - **帧长**: 20ms (320字节/帧未压缩,约80字节/帧压缩后)
  - **延迟**: 编解码总延迟<50ms

**NFR-022a 功放芯片规格**
- **功放型号**: NS4150B (D类单声道音频功放)
- **输出功率**: 3W @ 4Ω, THD+N<10% (典型应用)
- **电源电压**: 2.5V-5.5V (兼容3.7V锂电池)
- **效率**: >85% (D类拓扑,低功耗)
- **输入接口**: 差分输入,连接ES8311 DAC输出
- **输出接口**: 单端BTL输出,驱动4Ω扬声器
- **保护功能**: 过温保护、短路保护、欠压保护
- **THD要求**: 符合NFR-020中AEC参考信号质量要求 (100Hz<10%, 200Hz<6%, 350Hz以上<3%)
- **关联需求**: NFR-020 (AEC参考信号回采), NFR-022 (ES8311输出驱动)

**NFR-022b 扬声器规格**
- **扬声器型号**: XHXDZ-2828-4R3W-2P
- **尺寸**: 28mm × 28mm (方形超薄扬声器)
- **阻抗**: 4Ω ±15%
- **额定功率**: 3W (匹配NS4150B功放输出)
- **频率响应**: 300Hz-12kHz (语音频段覆盖)
- **灵敏度**: 待定 (需参考数据手册)
- **类型**: 2针引脚(2P)
- **应用场景**: 适用于毛绒玩具等小型设备,体积紧凑
- **关联需求**: NFR-022a (功放驱动), FR-003 (AI语音回应播放)

**NFR-023 存储空间分配**
- **OTA分区0 (ota_0)**: 3MB (应用固件,活动分区或待升级分区)
- **OTA分区1 (ota_1)**: 3MB (应用固件,活动分区或待升级分区)
- **OTA Data分区**: 8KB (记录当前活动分区和升级状态)
- **系统提示音分区**: ≤2MB (OGG格式,支持中英文两种语言,单语言包≤1MB)
- **预设音效分区**: ≤500KB (≤10个非语言音效文件,OGG格式,用于多模态反馈)
- **NVS分区**: ≤512KB (WiFi凭证至少30个、设备配置、语言设置、角色配置、OTA状态等)
- **其他预留**: ≤500KB (工厂分区、引导加载程序、分区表等)
- **总Flash需求**: ≥8MB (推荐8MB或16MB ESP32S3模组)
- **分区表类型**: 自定义分区表,支持OTA双分区+独立资源分区
- **关联需求**: FR-051 (OTA双分区方案)

**NFR-024 多语言支持技术规格**
- **语言种类**: 支持中文和英文两种语言
- **切换方式**: 支持固件编译时配置(menuconfig)和云端动态配置两种方式
- **配置优先级**: 云端配置 > 固件默认配置
- **语音包格式**: OGG格式Opus封装,单语言包大小≤1MB
- **热更新机制**: 设备联网后可从云端下载新语言包并替换本地提示音,下载失败时回退至当前语言包
- **存储位置**: 语音包存储在Flash独立分区,支持动态替换不影响固件区
- **切换延迟**: 云端下发语言配置后,设备在下次联网时应用新语言,切换过程无需重启
- **关联需求**: FR-045至FR-050

**NFR-025 网络通信协议**
- **WiFi标准**: 802.11 b/g/n (2.4GHz频段)
- **信号要求**: ≥-70dBm时保证稳定连接,<-85dBm时可能断开
- **蓝牙**: BLE 4.2 (低功耗蓝牙,仅用于配网)
- **传输协议**: WebSocket (语音流) + HTTP/HTTPS (控制消息)
- **带宽需求**: 上行32kbps (音频上传) + 下行32-64kbps (TTS下载)

**NFR-026 震动电机硬件规格**
- **电机类型**: 偏心转子电机(ERM, Eccentric Rotating Mass)或线性谐振驱动器(LRA, Linear Resonant Actuator)
- **推荐方案**: ERM (成本低、驱动电路简单、适合玩具应用)
- **工作电压**: 2.5V-3.7V (兼容锂电池直供或GPIO驱动)
- **工作电流**: <100mA @ 3.7V (峰值电流)
- **驱动方式**: GPIO + MOSFET/三极管驱动,PWM频率1-10kHz
- **响应时间**: 启动响应时间<50ms,停止响应时间<50ms
- **震动频率**: ERM: 100-200Hz典型值; LRA: 谐振频率150-250Hz
- **使用寿命**: >100万次启停周期
- **保护电路**:
  - 限流电阻或电流限制电路
  - 反向二极管保护(防止电机反向电动势损坏GPIO)
  - 可选:过流保护和热保护
- **震动模式控制**:
  - PWM占空比控制震动强度:0%(停止) - 100%(最强)
  - 软件定时器控制震动时长和间隔,支持复杂震动模式编程
- **安装要求**: 电机应固定在PCB或内部结构上,避免共振干扰其他传感器(特别是IMU)
- **关联需求**: FR-005c, FR-037至FR-040

- **SC-012** (仅WiFi+4G版): 4G在弱信号环境(RSSI -100dBm)下数据传输成功率≥90%,WiFi/4G/BLE三模共存时各模块性能下降<15% → 详见 NFR-010c

## 6. 假设与依赖

### 6.1 技术假设

1. **AI服务可用性**: 假设存在可用的云端AI对话服务API,盒子通过WiFi网络访问该服务获取对话回应
2. **手机APP/小程序就绪**: 假设配套的手机APP或微信小程序已开发完成,能够提供蓝牙配对和WiFi配置功能
3. **语音识别与合成**: 假设采用行业标准的语音识别(ASR)和语音合成(TTS)服务,识别准确率和合成质量达到商用水平
4. **电池容量**: 假设盒子配备容量不低于1500mAh的锂电池,能够满足NFR-016定义的续航要求
5. **网络依赖**: AI对话服务完全依赖互联网连接,离线状态下通过预设音效和震动反馈保持基本交互体验(详见FR-037至FR-040, FR-005c)
6. **单用户使用**: 假设盒子主要为单个用户设计,不需要支持多用户账户或个性化配置(如未要求多用户功能)
7. **存储容量**: 假设ESP32S3模组配备足够的Flash存储空间(≥4MB),能够容纳固件、系统提示音和必要的系统数据,详见NFR-023
8. **环境噪音处理**: 假设双麦克风阵列具备基本的噪音抑制和回声消除能力,能够在典型家庭环境(噪音<60dB)下正常工作,详见NFR-020
9. **数据隐私**: 所有语音数据通过加密连接传输,处理后立即删除不保留,遵循中国《个人信息保护法》等相关隐私保护规定,详见NFR-012, NFR-014

### 6.2 依赖与约束

**外部依赖**

- 云端AI对话服务API的可用性和响应速度 → 详见NFR-008
- 手机APP/微信小程序的蓝牙和WiFi配置功能
- 用户家庭2.4GHz WiFi网络的可用性和稳定性 → 详见NFR-025
- 语音识别(ASR)和语音合成(TTS)第三方服务

**技术约束**

- ESP32S3模组的计算能力和存储空间限制 → 详见NFR-023
- **双麦克风阵列**: 阵列的噪音抑制和打断检测能力,必须基于乐鑫(Espressif)官方提供的AEC(Acoustic Echo Cancellation/声学回声消除)功能组件进行开发。这旨在确保在扬声器播放AI语音或其他音频时,依然能有效消除回声,准确捕捉用户的语音输入,从而实现可靠、低延迟的"打断"(Barge-in)功能 → 详见NFR-020

**业务约束**

- 产品需符合电子产品安全标准(如GB 4943.1信息技术设备安全)

## 9. 技术参考文档

### 9.1 音频前端设计

#### 音频硬件选型方案 (关联: NFR-020, NFR-022, NFR-022a, NFR-022b)

**完整音频链路**:
```
[用户语音] → [LMA3729T381麦克风×2] → [ES7210 ADC] → [ESP32S3 I2S] → [云端ASR]
[云端TTS] → [ESP32S3 I2S] → [ES8311 DAC] → [NS4150B功放] → [XHXDZ-2828扬声器] → [用户]
```

**音频采集链路**:
- **麦克风**: LMA3729T381-OY3S × 2 (模拟麦克风,兼容MSM381A3729H9BPC封装)
  - 间距: 45mm (符合乐鑫官方建议4~6.5cm)
  - 用途: 双麦克风阵列,支持声源识别和波束成形
- **ADC芯片**: ES7210 (4通道24位ADC)
  - 接口: I2S连接至ESP32S3
  - 采样率: 16kHz (可配置8k-96kHz)
  - 位深度: 24bit
  - 通道: 使用2通道连接双麦克风,预留2通道可扩展

**音频输出链路**:
- **Codec芯片**: ES8311 (低功耗音频编解码器)
  - 接口: I2S连接至ESP32S3
  - DAC: 24位,支持8k-96kHz采样率
  - 输出: 差分输出至NS4150B功放
  - AEC回采: ADC可回采PA前级参考信号用于AEC算法
- **功放芯片**: NS4150B (D类单声道功放)
  - 输出功率: 3W @ 4Ω
  - 效率: >85% (低功耗)
  - 保护: 过温/短路/欠压保护
  - THD: 符合AEC要求 (100Hz<10%, 200Hz<6%, 350Hz以上<3%)
- **扬声器**: XHXDZ-2828-4R3W-2P
  - 尺寸: 28×28mm方形超薄
  - 阻抗: 4Ω
  - 功率: 3W (匹配功放输出)
  - 频响: 300Hz-12kHz (语音频段)

**选型优势**:
1. **低功耗**: ES8311和NS4150B均为低功耗设计,延长电池续航
2. **高集成度**: ES7210支持4通道,预留扩展空间
3. **AEC友好**: ES8311 ADC可回采参考信号,配合乐鑫AEC算法实现可靠打断
4. **紧凑体积**: XHXDZ-2828超薄扬声器适合毛绒玩具内部空间

**乐鑫麦克风设计指南**
- **文档链接**: [Espressif Microphone Design Guidelines](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32/audio_front_end/Espressif_Microphone_Design_Guidelines.html)
- **关键设计参数**:

#### 麦克风阵列间距 (关联: NFR-020)
- **双麦克风方案**: 麦克风间距应保持 **4~6.5 cm**
- **轴线要求**: 麦克风轴线应平行于水平线
- **本项目采用**: 双麦克风阵列,间距范围 40-65mm (优化后从"30-40mm待定"调整为符合官方建议)

#### 麦克风与扬声器布局 (关联: NFR-020)
- **隔离要求**: 麦克风应远离扬声器等会产生噪音或振动的物体
- **缓冲设计**: 麦克风与扬声器音腔之间应通过橡胶垫等材料隔离缓冲
- **目的**: 减少扬声器振动对麦克风的物理干扰,提升AEC效果

#### 音频技术参数 (关联: NFR-020, NFR-022)
- **频率响应**: 50~16 KHz范围内波动应在 ±3 dB以内
- **最大声压级**: 麦克风拾音声压不应超过 102 dB (1KHz)
- **本项目采用**: 16kHz采样率,频响范围覆盖300Hz-12kHz(扬声器输出)

#### AEC回声消除硬件设计 (关联: NFR-020, FR-002)
- **参考信号采集**: 应尽量靠近扬声器侧,推荐从DA后级、PA(功率放大器)前级回采
- **功放THD要求**: 最大音量下
  - 100Hz: THD < 10%
  - 200Hz: THD < 6%
  - 350Hz以上: THD < 3%
- **D类功放滤波**: 从D类功放引参考信号时,需增加低通滤波器,截止频率推荐 > 22 KHz
- **本项目影响**: 确保AEC算法能准确消除扬声器回声,实现可靠的打断(Barge-in)功能
