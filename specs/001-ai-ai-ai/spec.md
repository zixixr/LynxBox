## 1. 产品概述

### 1.1 产品愿景

本项目旨在打造一款名为"LynxBox"的AI语音交互核心模组。通过将LynxBox永久植入毛绒玩具等传统物品中,我们能将其升级为具备智能对话、动作感知与情感交互能力的AI伙伴,为用户提供新颖、温暖的陪伴体验。

### 1.2 核心功能

- **实时AI对话**: 基于云端AI服务,实现自然、流畅的语音对话交互
- **语音唤醒词**: 支持"Hello 灵犀"唤醒词,用户在待机状态下说出唤醒词即可启动对话,无需按钮操作
- **双麦克风打断**: 允许用户在AI回应过程中随时打断并输入新指令,模拟真实交流
- **动作感知交互**: 内置IMU传感器,可识别摇晃、翻转、轻拍等动作,并让AI在对话中做出相应反馈
- **多模态反馈**: 结合语音、音效和触觉震动反馈,在未被语音/晃动唤醒时播放预设音效和震动,增强交互生命感
- **无线连接与便捷配网**: 支持2.4GHz WiFi,通过蓝牙辅助手机APP/小程序快速完成网络配置
- **智能电源管理**: 包含低电量提醒、充电保护、自动休眠与唤醒等机制,确保安全与续航

### 1.3 关键技术规格

| 组件 | 规格 |
|------|------|
| **主控** | ESP32-S3-WROOM-1-N16R8 模组 (Xtensa LX7双核, 240MHz, 512KB SRAM + 8MB PSRAM, 16MB Flash) |
| **音频输入** | ES7210 ADC + 2个LMA3729T381-OY3S模拟麦克风(兼容MSM381A3729H9BPC), I2S接口, 间距45mm |
| **音频输出** | ES8311 Audio Codec + NS4150B功放 + XHXDZ-2828-4R3W-2P扬声器(4Ω 3W) |
| **传感器** | QMI8658 IMU惯性测量单元(6轴加速度+陀螺仪) |
| **触觉反馈** | 1034 ERM震动马达(3V/80mA), GPIO驱动, 支持震动强度和模式控制 |
| **连接性** | WiFi 2.4GHz (802.11 b/g/n), 蓝牙4.2 BLE |
| **物理交互** | 拨动开关(ON/OFF开关机) + M键按钮(单击/双击/长按), LED指示灯, 触摸引脚预留(ESP32S3内置触摸传感器,最多支持14路), 双眼屏幕GPIO预留(SPI/I2C接口,用于AI玩具表情显示) |
| **电源** | 1200mAh锂聚合物电池,USB-C充电,电量检测电路,NTC温度传感器(电池温度监测) |
| **存储** | 16MB Flash + 8MB PSRAM (支持OTA双分区+资源分区; 选型: ESP32-S3-WROOM-1-N16R8) |

### 1.4 硬件版本规划

本产品设计两款硬件版本，除网络连接模块外其他硬件完全一致：

| 版本 | 网络模块 | 应用场景 | 附加要求 |
|------|---------|---------|---------|
| **WiFi版** | WiFi 2.4GHz + BLE | 家庭/办公室等有WiFi环境 | 成本优化，标准版 |
| **WiFi+4G版** | WiFi 2.4GHz + BLE + CAT1 4G模组 (eSIM) | 户外/移动场景，无WiFi环境 | 信号强度优化，抗干扰设计，功耗<150mA活跃/<5mA休眠 |

**WiFi+4G版技术要求**：采用CAT1 4G模组(如中移物联ML302/Air724UG等)，LTE Cat.1标准(上行5Mbps/下行10Mbps)，信号覆盖主流运营商频段(移动/联通/电信)，PCB天线隔离设计减少干扰，支持eSIM Profile下载。网络切换逻辑：优先WiFi → WiFi不可用时切换4G → WiFi恢复后切换回WiFi。

### 1.5 数据隐私技术原则

- **无痕处理**: 语音数据仅用于实时处理,不在设备端或云端存储
- **加密传输**: 数据传输采用TLS/SSL加密
- **本地化配置**: 仅在设备本地加密存储WiFi凭证等必要配置信息

### 1.6 典型使用场景

- 家庭陪伴: 作为日常对话伙伴,进行闲聊、讲故事、知识问答
- 情感互动: 通过语音和动作感知,提供情感回应和陪伴
- 多场景切换: 支持家庭/办公室等多WiFi环境自动切换

## 2. 用户场景与测试

### 用户故事 1 - 基本语音对话交互

用户首次使用AI语音盒子与毛绒玩具进行语音对话。用户拨动开关至ON位置开机，玩具发出欢迎提示音，用户直接对着玩具说话，玩具能够识别语音并通过内置扬声器回应，实现自然的双向对话交互。

**为什么是此优先级**: 语音对话是产品的核心价值主张，没有此功能产品无法使用。这是最小可行产品(MVP)的基础。

**独立测试**: 可通过开机后直接与玩具对话并接收语音回复来完整测试。交付价值:用户获得与玩具对话的基本体验。

**验收场景**:

1. **Given** 盒子处于关机状态, **When** 用户拨动开关至ON位置, **Then** 盒子立即开机并播放开机音乐
2. **Given** 盒子已完成网络配置并开机, **When** 开机成功联网后, **Then** 盒子主动播放后台准备的"问候语"
3. **Given** 盒子已开机并完成网络配置, **When** 用户说"你好", **Then** 盒子在1.5秒内通过扬声器回应
4. **Given** 盒子处于待机状态(非休眠), **When** 用户说"Hello 灵犀", **Then** 盒子播放唤醒提示音(如"叮"声)并进入对话模式,等待用户继续说话
5. **Given** 盒子通过唤醒词进入对话模式, **When** 用户继续说"今天天气怎么样", **Then** 盒子识别语音并通过AI回应天气信息
6. **Given** 盒子通过唤醒词进入对话模式, **When** 15秒内无有效语音输入, **Then** 盒子自动退出对话模式回到待机状态
7. **Given** 用户正在与盒子对话, **When** 用户在盒子说话过程中打断说"等一下", **Then** 盒子立即停止当前语音输出并等待新的用户输入
8. **Given** 盒子正在播放AI回应, **When** 用户摇晃玩具(IMU检测到动作), **Then** 盒子识别动作并在语音回应中提及"我感觉到你在和我玩"

### 用户故事 2 - 初次配网设置

用户购买产品后,首次开机需要通过手机APP或小程序为盒子配置WiFi网络连接,使盒子能够访问互联网进行AI对话服务。

**为什么是此优先级**: 虽然是首次使用的必需步骤,但可以通过离线模式(预设对话)实现P1的基本测试。配网是产品正常使用的前提,但不阻碍核心功能演示。

**独立测试**: 可通过全新盒子从开机到成功连接WiFi的完整流程独立测试。交付价值:用户能够自主完成设备联网。

**验收场景**:

1. **Given** 盒子首次开机且未绑定, **When** 开机完成, **Then** 盒子播放提示音"请使用手机APP连接我"并自动进入蓝牙配对模式
2. **Given** 盒子处于蓝牙配对模式, **When** 用户在手机APP中搜索并连接盒子蓝牙, **Then** APP显示"已连接设备"并显示可用WiFi网络列表
3. **Given** APP显示WiFi列表, **When** 用户选择家庭WiFi并输入密码点击连接, **Then** 盒子连接成功并播放提示音"网络连接成功",该WiFi凭证被保存
4. **Given** 盒子已配置1个或多个网络, **When** 盒子断电重启, **Then** 盒子自动扫描并连接已保存的可用WiFi网络(按信号强度优先)无需重新配置
5. **Given** 盒子配网失败(密码错误或信号弱), **When** 连接超时, **Then** 盒子播放提示音"网络连接失败,请重试"并保持蓝牙配对模式
6. **Given** 盒子已保存家庭和公司两个WiFi, **When** 用户带着玩具从家到公司, **Then** 盒子检测到家庭WiFi信号丢失后自动扫描并连接到公司WiFi
7. **Given** 用户需要添加新的WiFi网络, **When** 用户通过APP添加第3个WiFi, **Then** 新WiFi凭证被保存,盒子可存储并管理多个网络
8. **Given** 盒子已绑定但所有WiFi不可用, **When** 用户语音或摇晃唤醒盒子, **Then** 盒子播放提示音"网络未连接,请前往小程序配网",不自动进入配网模式
9. **Given** 盒子已绑定但未联网, **When** 用户长按M键3秒, **Then** 盒子播放提示音"正在进入配网模式"并启动蓝牙配对模式

### 用户故事 3 - 电源管理

用户需要管理盒子的电源状态,包括充电提醒、低电量警告、以及正常关机,确保设备使用安全和良好的用户体验。

**为什么是此优先级**: 电源管理是产品可用性的重要保障,但不影响核心对话功能的演示和测试。可以在基本功能验证后再实现完整的电源管理逻辑。

**独立测试**: 可通过模拟不同电量状态(充电中、低电量、关机)独立测试。交付价值:用户能够安全使用和维护设备。

**验收场景**:

1. **Given** 盒子电量低于15%, **When** 电量触发低电警告, **Then** 盒子每隔5分钟播放提示音"电量不足,请充电"
2. **Given** 盒子正在使用, **When** 用户连接充电线, **Then** 盒子播放提示音"开始充电"且保持全部交互可用
3. **Given** 盒子正在充电, **When** 用户断开充电线, **Then** 盒子播放提示音"充电断开",并停止充电指示
4. **Given** 盒子正在充电, **When** 电量达到100%, **Then** 盒子播放提示音"充电完成"
5. **Given** 盒子处于开机状态, **When** 用户拨动开关至OFF位置, **Then** 盒子播放关机音乐并语音提示"再见,下次见"后关闭电源
6. **Given** 盒子电量低于5%, **When** 电量耗尽, **Then** 盒子播放提示音"电量耗尽,即将关机"后自动关机

### 用户故事 4 - 设备解绑与云端重置

用户在需要转让设备或更换账号时,能够通过小程序安全地解绑设备,云端自动下发重置指令,设备清除所有个人配置和数据后恢复到出厂状态。

**为什么是此优先级**: 解绑功能主要用于设备转让和账号管理场景,使用频率低,不影响日常使用和核心功能。采用小程序解绑而非物理按钮,提供了类似智能手机的安全保护机制。

**独立测试**: 可通过小程序发起解绑并验证设备恢复到初始状态独立测试。交付价值:用户能够安全地转让设备,防止设备丢失后被他人使用。

**验收场景**:

1. **Given** 用户在小程序中打开"设备管理", **When** 用户点击"解绑设备"并输入验证码确认, **Then** 云端标记设备为"待解绑"状态并推送解绑指令
2. **Given** 设备在线且收到云端解绑指令, **When** 设备接收到指令, **Then** 盒子播放提示音"设备即将解绑,所有数据将被清除",LED闪烁红色3次
3. **Given** 解绑提示播放完成, **When** 3秒后开始重置, **Then** 盒子清除所有WiFi配置、设备绑定Token、用户配置,播放"设备已重置,请重新配对"
4. **Given** 重置完成, **When** 设备自动重启, **Then** 盒子进入蓝牙配对模式,表现如同全新设备
5. **Given** 设备离线(无WiFi/4G)时用户发起解绑, **When** 云端标记"待解绑", **Then** 设备下次联网时自动执行重置流程
6. **Given** 设备已被原主人解绑但未联网执行重置, **When** 新用户尝试绑定, **Then** 盒子提示"该设备已绑定其他账号,请联系原主人解绑"并拒绝绑定

### 用户故事 5 - 动作识别交互增强

用户在与玩具对话时,通过摇晃、翻转、轻拍等物理动作与玩具互动,盒子通过IMU传感器识别这些动作,并在AI对话中做出相应反应,增强互动趣味性。

**为什么是此优先级**: 动作识别是锦上添花的增强功能,能显著提升用户体验和产品差异化,但不是基本对话功能所必需。

**独立测试**: 可通过执行特定动作(摇晃、翻转、轻拍)并验证AI回应是否包含动作相关内容独立测试。交付价值:用户获得更丰富、更有趣的互动体验。

**验收场景**:

1. **Given** 盒子处于对话模式, **When** 用户快速摇晃玩具3次, **Then** 盒子识别为"摇晃"动作并在对话中回应"哇,你在摇我,好好玩!"
2. **Given** 盒子处于对话模式, **When** 用户将玩具翻转180度(倒置), **Then** 盒子识别为"翻转"动作并回应"呀,我被翻过来了,好晕呀"
3. **Given** 盒子处于对话模式, **When** 用户轻拍玩具2次, **Then** 盒子识别为"轻拍"动作并回应"你在拍我吗?再来一次!"
4. **Given** 盒子处于空闲状态超过5分钟, **When** 用户拿起玩具(IMU检测到移动), **Then** 盒子主动语音问候"你回来啦,我们聊聊吧"

### 用户故事 6 - 动作唤醒交互

用户在玩具处于休眠状态时,通过拿起或摇晃等动作直接唤醒设备,并立即开始互动,获得一种"即拿即玩"的无缝体验,无需寻找并按下小按钮。

**为什么是此优先级**: 这是提升产品"生命感"和易用性的重要功能,降低了交互门槛,增强了产品的主动性和灵性,但不影响核心对话流程的实现。

**独立测试**: 可通过将设备置于休眠状态,然后执行"拿起"动作,验证设备是否能被唤醒并主动问候。交付价值:降低了用户的交互门槛,增强了产品的灵性和主动性。

**验收场景**:

1. **Given** 盒子已联网并进入休眠状态, **When** 用户拿起玩具(IMU检测到持续位移), **Then** 盒子在2秒内被唤醒并主动播放问候语,如"你回来啦,我们聊聊吧!"
2. **Given** 盒子未联网并进入休眠状态, **When** 用户拿起玩具, **Then** 盒子被唤醒,并播放配网提示音"请使用手机APP连接我",同时进入蓝牙配对模式
3. **Given** 盒子处于休眠状态, **When** 用户摇晃玩具(快速摇晃≥2次), **Then** 盒子被唤醒,效果等同于"拿起"动作唤醒
4. **Given** 盒子通过动作唤醒后已联网, **When** 唤醒完成, **Then** 盒子自动重连WiFi并恢复到待机状态,准备接收语音输入

### 用户故事 7 - OTA固件升级

用户需要为设备升级固件以获取新功能、性能优化和安全补丁,通过OTA(空中升级)方式无需拆机或连接电脑,实现便捷、安全的固件迭代。

**为什么是此优先级**: OTA升级是设备持续优化的基础能力,虽然不是首次使用必需,但对产品长期迭代和问题修复至关重要,支持灰度发布可降低升级风险。

**独立测试**: 可通过模拟云端推送固件更新,测试设备自动检测、下载、安装、回滚等完整流程。交付价值:设备可持续迭代优化,降低维护成本。

**验收场景**:

1. **Given** 盒子已联网且电量≥50%, **When** 云端发布新版本固件(设备在5%灰度范围内), **Then** 设备自动检测到更新并播放提示音"发现新版本固件,是否升级?",APP推送通知
2. **Given** 设备检测到固件更新且用户确认升级, **When** 开始下载固件, **Then** 设备通过HTTPS下载固件到非活动分区,实时上报进度(0%-100%),LED呼吸灯闪烁
3. **Given** 固件正在下载(进度50%), **When** 网络中断, **Then** 设备暂停下载,网络恢复后从50%位置断点续传,无需重新下载
4. **Given** 固件下载完成, **When** 设备校验SHA256和签名, **Then** 校验通过后播放"固件升级中,请勿断电"并开始写入Flash,禁用所有交互功能
5. **Given** 固件写入完成, **When** 设备重启, **Then** 启动新固件,上报版本号到云端,播放"固件升级成功,当前版本:vX.X.X",WiFi凭证等配置100%保留
6. **Given** 新固件启动失败(连续3次重启失败), **When** 检测到启动异常, **Then** 自动回滚到旧版本固件,播放"升级失败已回滚",上报云端并通过APP通知用户
7. **Given** 设备电量<30%, **When** 检测到固件更新, **Then** 设备拒绝升级并播放"电量不足,请充电后再升级"
8. **Given** 设备不在当前灰度范围(如95%设备未被选中), **When** 设备请求升级, **Then** 云端返回"暂无可用更新",设备继续使用当前版本
9. **Given** 用户通过APP主动触发升级检查, **When** 云端有新版本且设备符合条件, **Then** 立即开始升级流程,无需等待24小时自动检测
10. **Given** 云端停止灰度发布(紧急停止), **When** 设备请求升级, **Then** 云端返回"暂无可用更新",已下载未安装的设备不执行升级

### 用户故事 8 - WiFi/4G网络切换

用户使用WiFi+4G版LynxBox时,需要根据实际网络状况在WiFi和4G之间灵活切换,既能享受WiFi的稳定高速,又能在WiFi信号差时快速切换到4G,保证语音交互的流畅性。

**为什么是此优先级**: 网络切换是WiFi+4G版的核心差异化功能,直接影响户外和移动场景的用户体验,但不影响WiFi版用户和基本对话流程。

**独立测试**: 可通过在WiFi和4G网络环境下测试双击M键切换网络,验证切换速度和语音提示。交付价值:用户可根据实际需求自主选择网络模式。

**验收场景**:

1. **Given** 盒子当前使用WiFi模式,WiFi和4G均可用, **When** 用户双击M键, **Then** 盒子立即播放"已切换至4G模式",在2秒内完成切换,连接成功后播放"网络连接成功",LED显示绿色常亮
2. **Given** 盒子当前使用4G模式, **When** 用户双击M键, **Then** 盒子立即播放"已切换至WiFi模式",在3秒内完成切换,连接成功后播放"网络连接成功",LED显示蓝色常亮
3. **Given** 用户手动切换到4G模式, **When** WiFi信号恢复正常, **Then** 盒子保持4G模式不自动切换,直到用户下次手动切换或重启设备
4. **Given** 盒子开机时WiFi可用, **When** 设备启动网络连接流程, **Then** 盒子优先连接WiFi,若5秒内未连接成功则自动切换至4G,首次连接成功播放"网络连接成功"
5. **Given** 盒子WiFi连接断开1分钟后重连成功, **When** 网络恢复, **Then** 静默恢复服务,不播放"网络连接成功"提示音(断线时长<2分钟)
6. **Given** 盒子WiFi连接断开5分钟后重连成功, **When** 网络恢复, **Then** 播放"网络连接成功"提示音,告知用户网络已恢复(断线时长≥2分钟)
7. **Given** 盒子正在进行语音对话, **When** 用户双击M键切换网络, **Then** 当前对话立即中断,切换完成后用户可重新发起对话
8. **Given** 盒子处于休眠状态, **When** 用户双击M键, **Then** 无响应
9. **Given** WiFi版设备, **When** 用户双击M键, **Then** 无响应

### 2.6 边界情况与异常处理

| 场景 | 系统行为 |
|------|----------|
| 用户持续打断(连续3次以上) | 正常响应每次打断,不做特殊处理 |
| WiFi信号丢失或网络中断 | 播放提示音"网络连接失败,请检查网络"并停止对话服务,直到网络恢复 |
| 云端AI服务超时/不可用 | 自动重试1次(总计2次,每次超时2秒),仍失败则播放"服务暂时不可用" |
| 蓝牙配对10分钟无连接 | 自动进入休眠状态,单击M键可唤醒并重新进入配对模式 |
| 充电时电池温度>50°C | 立即停止充电并播放警告"温度过高,已停止充电",降至45°C恢复;连续3次超温则停止充电并关机 |
| 充电期间用户尝试交互 | 正常响应交互,不做特殊限制 |
| WiFi环境切换 | 自动检测信号丢失并扫描连接其他已保存WiFi,切换过程对用户透明 |
| 所有已保存WiFi不可用 | 仅在语音或摇晃唤醒时检测网络状态,若未联网则播放提示音"网络未连接,请前往小程序配网";用户可通过长按M键3秒主动进入蓝牙配对模式 |
| 多麦克风输入(环境噪音/多人说话) | 优先处理信号强度最高、最稳定的麦克风输入,过滤远处背景噪音(需波束成形支持) |
| IMU检测剧烈震动(跌落) | 记录事件到日志,继续正常服务(无需暂停或自检) |
| 对话中断后恢复 | AI可主动询问"我刚才讲到一半,你还想继续听吗?"(上下文感知) |

## 3. 功能需求

### 3.1 硬件交互需求

**硬件交互需求**

- **FR-001 (拨动开关)**: 盒子必须配备物理拨动开关,支持硬件级开关机控制:
  - **开机**: 拨动开关至ON位置,设备立即上电并启动系统,播放开机音乐
  - **关机**: 拨动开关至OFF位置,设备播放关机音乐和"再见,下次见"后硬件断电
  - **状态可见**: 拨动开关位置直观显示设备开关机状态
  - *注: 拨动开关提供物理级电源隔离,防止误触发,符合儿童玩具安全设计规范*
- **FR-001a (M键按钮)**: 盒子必须配备M键按钮,根据设备状态响应不同操作:
  - **休眠状态下单击**: 唤醒设备
  - **休眠状态下长按3秒**: 唤醒设备并进入配网模式,播放"正在进入配网模式"
  - **活跃状态下单击**: 状态播报功能,触发双次短震(50ms × 2,间隔50ms)并根据网络状态响应:
    - 已联网: 调用AI生成简短在线确认语音(如"我在呢"、"有什么可以帮你"等自然回应)
    - 未联网: 播放系统提示音"网络未连接,请前往小程序配网"
  - **活跃状态下双击**: 切换WiFi/4G网络模式(仅WiFi+4G版),播放"已切换至WiFi/4G模式"
  - **活跃状态下长按3秒**: 进入配网模式,播放"正在进入配网模式"并启动蓝牙配对模式
  - *注: 双击识别算法见FR-059,双击间隔<500ms,首次点击后等待300ms判断是否双击*
- **FR-002**: 盒子必须通过双麦克风阵列实现实时语音输入,支持在播放音频时检测用户打断并立即停止播放
- **FR-003**: 盒子必须通过内置扬声器播放AI语音回应、系统提示音、开关机音乐
- **FR-004**: 盒子必须通过IMU传感器实时检测并识别至少以下几种用户动作:拿起、摇晃(区分快速和温柔)、翻转、轻拍、静置、跌落
- **FR-004a (动作定义参考)**: 上述动作的算法具体实现(例如加速度阈值、角速度变化、持续时间等参数)在详细设计阶段,应重点参考Project Magic项目的相关定义与实现,以确保动作识别的准确性和交互体验的自然流畅。跌落动作应触发保护性或安抚性回应
- **FR-005**: 盒子必须支持通过USB接口进行充电,并在充电状态改变时播放相应提示音
- **FR-006 (LED状态指示)**: 盒子必须通过LED指示灯显示设备状态:
  - 充电中:LED呼吸灯效果
  - 充电完成:LED绿色常亮
  - 充电异常(温度过高):LED红色闪烁
  - 说话状态(AI语音播放中):待定
  - 聆听状态(监听用户输入):待定
  - 待机状态:待定
  - *注: 说话、聆听、待机等工作状态的LED效果(颜色、闪烁模式、呼吸效果等)将在详细设计阶段定义*
- **FR-007 (触摸功能支持)**: 盒子硬件设计必须预留ESP32S3触摸引脚,支持外接铜箔实现触摸交互功能:
  - **引脚预留**: PCB设计必须预留至少2-4路触摸引脚(推荐GPIO1-GPIO14中选择),引脚需引出至可外接铜箔的焊盘或接口
  - **可选功能**: 触摸功能为可选功能,不外接铜箔时不影响盒子基本功能运行
  - **触摸检测**: 当外接铜箔并启用触摸功能时,盒子必须能检测到触摸事件
  - **灵敏度配置**: 触摸灵敏度阈值应可通过固件配置调节,适配不同铜箔面积和厚度
  - **用途举例**: 可用于实现抚摸互动(如抚摸玩具头部触发温柔回应)、触摸唤醒、触摸控制等扩展交互
  - *注: 具体触摸交互逻辑(动作定义、AI回应方式)在详细设计阶段根据实际应用场景定义*
- **FR-008 (震动反馈支持)**: 盒子必须配备1034 ERM偏心转子震动马达,支持多模态触觉反馈交互:
  - **电机规格**: 1034 ERM震动马达(10mm直径×3.4mm厚度, 3V/80mA, 偏心转子)
  - **驱动方式**: 通过ESP32S3 GPIO引脚驱动,使用PWM信号控制震动强度
  - **震动模式**: 支持可编程震动模式,参数包括:震动时长(ms)、间隔时长(ms)、震动强度(PWM占空比)
  - **预设模式**: 固件内置至少10种预设震动模式,包括:
    - 状态确认震动: 双次短震(50ms × 2, 间隔50ms),用于M键单击反馈
    - 其他震动模式在详细设计阶段定义
  - **电路保护**: 驱动电路需包含限流保护和反向二极管保护
  - **功耗要求**: 震动电机工作电流80mA @ 3V,支持快速启停(响应时间<10ms)
  - *注: 具体震动模式参数在详细设计阶段根据实际测试效果调优*
- **FR-009 (双眼屏幕GPIO预留)**: 盒子硬件设计必须预留GPIO引脚用于连接双眼屏幕(用于AI玩具表情显示),支持未来扩展:
  - **接口类型**: 预留SPI接口或I2C接口GPIO引脚,推荐SPI以支持更高刷新率
  - **SPI引脚预留**(推荐):
    - SCLK (时钟): 1路GPIO
    - MOSI (数据): 1路GPIO
    - CS (片选): 2路GPIO (左眼、右眼各1路,支持独立控制)
    - DC (数据/命令): 1路GPIO
    - RST (复位,可选): 1路GPIO
    - 背光控制(可选): 1路GPIO (支持PWM调节亮度)
    - **总计**: 最少5路GPIO(SCLK+MOSI+CS×2+DC),推荐7路(含RST+背光)
  - **I2C引脚预留**(备选):
    - SCL (时钟): 1路GPIO
    - SDA (数据): 1路GPIO
    - **总计**: 2路GPIO
  - **屏幕规格参考**(供硬件设计参考,非强制要求):
    - 推荐尺寸: 0.96-1.3英寸圆形或椭圆形OLED/TFT屏幕
    - 分辨率: 128×128或240×240像素
    - 显示内容: 眼睛表情(开心、困惑、眨眼等动画效果)
  - **可选功能**: 双眼屏幕为可选扩展功能,不连接屏幕时不影响盒子基本语音交互功能
  - **引脚引出**: 预留的GPIO需引出至PCB焊盘或预留接口(如排针),便于后续焊接屏幕模块
  - **电源供电**: 屏幕供电可从ESP32-S3的3.3V或5V引脚引出,需预留电源和地线
  - **设计考虑**: 引脚选择需避免与核心功能(I2S音频、IMU、WiFi天线等)冲突,建议使用GPIO16-GPIO21等灵活复用引脚
  - *注: 具体屏幕型号、驱动协议、动画设计在详细设计阶段根据实际产品形态定义*

**网络与连接需求**

- **FR-011**: 盒子必须支持2.4GHz WiFi(802.11 b/g/n)网络连接
- **FR-011**: 盒子的配网与绑定逻辑:
  - **首次开机(未绑定)**: 必须自动进入蓝牙配对模式,广播蓝牙信号供手机APP/小程序连接进行设备绑定
  - **已绑定但WiFi不可用**: 不自动进入配网模式,仅在语音或摇晃唤醒时检测网络状态,若未联网则播放提示音"网络未连接,请前往小程序配网"
  - **手动进入配网模式**: 用户可在任何时候通过长按M键3秒主动进入蓝牙配对模式
  - **4G版特殊说明**: WiFi+4G版在首次绑定时可不要求配网,允许先通过4G网络使用,后续再配置WiFi网络
- **FR-012**: 盒子必须在成功配对后,通过蓝牙接收来自手机APP的WiFi凭证(SSID和密码)并尝试连接
- **FR-013**: 盒子必须在WiFi连接成功后播放成功提示音并保存该网络凭证,连接失败后播放失败提示音并保持蓝牙配对模式
- **FR-014**: 盒子必须支持存储多个WiFi网络凭证(最多20个),每个凭证包含SSID、密码(加密存储)、上次连接时间
- **FR-014a**: 盒子在开机或网络断开时必须自动扫描周围WiFi,优先连接已保存网络中信号强度最强的可用网络
- **FR-014b**: 盒子在当前WiFi信号丢失时,必须自动扫描并尝试连接其他已保存的可用WiFi网络,无需用户干预
- **FR-014c**: 盒子必须支持通过APP管理已保存的WiFi网络,包括添加新网络、删除已保存网络、查看已保存网络列表

**语音交互需求**

- **FR-015**: 盒子必须能够采集用户语音输入并通过网络传输至云端ASR服务进行语音识别,将识别结果(文本)用于AI处理
- **FR-016**: 盒子必须能够接收云端TTS服务生成的语音数据并通过扬声器播放
- **FR-017**: 盒子必须支持两种打断模式:
  - **模式1-关键词打断**: 当用户说出特定关键词(如"等一下""停一下""暂停")时,盒子立即停止播放并等待新输入
  - **模式2-语音检测打断**: 只要双麦克风检测到用户开始说话(基于AEC处理后的语音能量检测),盒子立即停止播放
- **FR-017a**: 打断模式可通过云端配置选择,默认使用模式2(语音检测打断),响应时间≤500ms
- **FR-018**: 盒子必须在检测到用户动作(通过IMU)时,将动作信息作为上下文传递给AI,使AI回应能够关联用户动作
- **FR-019**: 盒子必须在网络连接正常时提供完整的在线AI对话服务
- **FR-019a**: 盒子在网络未连接或中断时,必须播放提示音"网络未连接,请先配置网络"或"网络连接失败,请检查网络",不提供对话服务
- **FR-019b**: 盒子在云端AI服务请求失败或超时(超时阈值2秒)时,必须自动重试1次,若仍失败则播放提示音"服务暂时不可用,请稍后再试"
- **FR-020 (语音唤醒词)**: 盒子在非休眠状态(待机状态)下必须支持语音唤醒词"Hello 灵犀"功能:
  - **唤醒词识别**: 设备持续监听麦克风输入,检测到唤醒词"Hello 灵犀"(中文发音)时触发对话模式
  - **状态限制**: 仅在非休眠状态下启用语音唤醒词检测,休眠状态下不检测唤醒词(仅支持按钮和IMU动作唤醒)
  - **识别方式**: 采用云端ASR识别或本地轻量级唤醒词模型(如ESP-SR),优先考虑本地模型以降低延迟和网络依赖
  - **唤醒反馈**: 检测到唤醒词后,播放简短提示音(如"叮"声)或震动反馈,表示进入对话模式,然后等待用户继续说话
  - **误唤醒防护**: 唤醒词识别阈值应设置合理,避免环境噪音或相似发音导致误唤醒,目标误唤醒率<5%
  - **功耗优化**: 待机状态下麦克风持续监听功耗应≤50mA,通过低功耗唤醒词检测算法优化
  - **唤醒后对话**: 唤醒后进入对话模式,用户可直接说话,设备将语音传输至云端AI处理并回应
  - **超时机制**: 唤醒后若15秒内无有效语音输入,自动退出对话模式回到待机状态
  - *注: 具体唤醒词模型选型(ESP-SR/云端ASR)在详细设计阶段确定,优先本地模型以提升用户体验*

**音频提示需求**

- **FR-021**: 盒子必须内置以下系统提示音:
  - **基础交互**: 开机音乐、关机音乐、请使用手机APP连接
  - **网络相关**: 网络连接成功、网络连接失败、网络未连接请前往小程序配网、正在进入配网模式、网络延迟过高请稍后再试
  - **网络切换(4G版)**: 已切换至WiFi模式、已切换至4G模式
  - **电源管理**: 开始充电、充电完成、充电断开、电量不足、电量不足请充电后再升级、电量耗尽、温度过高已停止充电
  - **设备管理**: 设备即将解绑所有数据将被清除、设备已重置请重新配对、该设备已绑定其他账号请联系原主人解绑
  - **OTA升级**: 发现新版本固件是否升级、固件升级中请勿断电、固件升级成功、升级失败请重试、升级失败已回滚
  - **异常情况**: 服务暂时不可用
  - *注: 所有提示音采用OGG格式,单个文件≤50KB,总大小≤2MB,支持多语言版本(中文/英文)*
- **FR-022**: 盒子必须在特定系统事件触发时自动播放对应提示音
- **FR-023**: 盒子必须确保系统提示音优先级高于AI语音播放,在播放提示音时暂停AI语音

**电源管理需求**

- **FR-024**: 盒子必须在电量低于15%时每隔5分钟播放一次低电量提示音
- **FR-025**: 盒子必须在电量低于5%时播放电量耗尽提示音并自动关机
- **FR-026**: 盒子必须在连接充电器时播放充电提示音"开始充电"; 断开充电器时播放提示音"充电断开",并停止充电指示
- **FR-027**: 盒子必须在充电完成(电量达100%)时播放充电完成提示音
- **FR-027a**: 盒子在充电状态下允许所有交互功能(语音对话、按钮、IMU动作识别等)正常使用; 温度或电量异常时按FR-027b/FR-027c执行保护措施
- **FR-027b (温度监测与保护)**: 盒子必须在充电过程中持续监测电池温度(采样频率≥1次/秒),当温度超过50°C时立即停止充电(2秒内完成保护动作)并播放警告提示音"温度过高,已停止充电",温度降至45°C以下时自动恢复充电
  - **温度阈值设定依据**: 基于Li-ion电池安全标准和ESP32实际应用经验:
    - Li-ion电池安全充电温度范围: 0°C ~ 45°C (推荐), 最高不超过50°C
    - 业界标准: 多数充电器禁止在50°C以上充电,60°C为锂电池安全运行极限
    - 消费电子产品实践: ESP32系统可工作至85°C,电池在50°C以下充电仍在安全范围内
    - 5°C滞环设计(50°C停止/45°C恢复)可有效防止温度在阈值附近波动导致的频繁开关充电
    - AI玩具使用场景: 考虑到可能在较温暖的环境中使用(如夏季室内),50°C阈值比45°C更实用,减少误触发
  - **保护响应时间**: 检测到温度>50°C后2秒内必须断开充电电路
  - **恢复条件**: 温度持续低于45°C超过30秒后方可恢复充电,避免温度刚降下又快速回升
- **FR-027c (极端过温保护)**: 盒子在充电温度异常(连续3次超温保护,即3次达到>50°C)时必须停止充电并保持关机状态,LED红色快速闪烁(2Hz)5秒后熄灭,需要用户拔出充电线等待冷却
  - **连续超温判定**: 在单次充电周期内,累计触发3次温度>50°C保护,且每次间隔<10分钟,判定为电池或环境异常
  - **安全关机**: 播放提示音"充电异常,设备将关机,请联系客服"后自动关机
  - **恢复方式**: 必须断开充电线并等待至少30分钟冷却后,重新插入充电线才能尝试再次充电
- **FR-028**: 盒子必须在任何状态下(包括蓝牙配对模式、待机、对话空闲)连续10分钟无用户交互(无语音输入、无按钮操作、无IMU动作)时自动进入休眠状态
- **FR-029**: 盒子在休眠状态下必须关闭蓝牙广播、WiFi连接、麦克风监听,仅保持按钮唤醒和IMU动作唤醒功能
  - *注: WiFi断开的省电效果需实测验证,若WiFi保持连接功耗增加不显著,可优化为保持WiFi连接以加快唤醒响应*
- **FR-030**: 用户在休眠状态下单击M键必须唤醒盒子
- **FR-030a (动作唤醒)**: 在休眠状态下,当IMU检测到指定的唤醒动作时,设备也必须自动唤醒,其效果等同于按钮唤醒:
  - **唤醒动作定义**: "拿起"(加速度>1.5G + 角度变化>30°)或"中等强度摇晃"
  - **防误触设计**: 通过提高加速度阈值(2.0G)排除轻微晃动和日常运输振动,降低误唤醒概率
- **FR-030b (唤醒后行为)**: 无论是通过按钮还是动作唤醒,设备恢复到休眠前的状态。具体行为如下:
  - **已绑定且已配网**: 重连WiFi(或4G)并进入待机状态;若网络连接成功,应主动发起问候语音
  - **已绑定但未联网**: 播放提示音"网络未连接,请前往小程序配网",不自动进入配网模式
  - **未绑定**: 进入蓝牙配对模式,播放提示音"请使用手机APP连接"

**设备管理需求**

- **FR-031 (小程序解绑)**: 用户必须能够通过小程序安全地解绑设备,解绑操作需要验证码/密码确认,防止误操作:
  - **解绑流程**: 用户在小程序点击"解绑设备"→输入验证码确认→云端标记设备为"待解绑"状态→推送解绑指令到设备
  - **安全验证**: 解绑操作需要输入微信密码或短信验证码,防止误操作或他人恶意解绑
  - **离线解绑**: 设备离线时,云端标记"待解绑"状态,设备下次联网时自动执行重置流程
  - **超时机制**: 设备超过30天未联网执行重置,云端强制解绑,允许用户重新绑定新设备
- **FR-032 (云端重置指令)**: 盒子必须支持接收云端下发的重置指令并执行恢复出厂设置:
  - **重置提示**: 收到解绑指令后,播放"设备即将解绑,所有数据将被清除",LED闪烁红色3次
  - **数据清除**: 清除所有WiFi凭证(最多20个)、设备绑定Token、用户配置(音量/语言/网络偏好),保留固件版本
  - **重置完成**: 播放"设备已重置,请重新配对",自动重启并进入蓝牙配对模式
- **FR-033 (防盗保护机制)**: 盒子必须实现类似智能手机的激活锁功能,防止设备丢失后被他人使用:
  - **绑定检查**: 新用户尝试绑定已绑定设备时,提示"该设备已绑定其他账号,请联系原主人解绑"并拒绝绑定
  - **云端验证**: 设备绑定状态由云端管理,仅在云端确认解绑后才允许重新绑定
  - **丢失保护**: 设备丢失后,原主人可通过小程序远程解绑,设备下次联网自动清除数据

**数据隐私需求**

- **FR-034**: 盒子必须通过加密连接(TLS/SSL)将语音数据实时传输到云端AI服务
- **FR-035**: 盒子本地不得存储任何用户语音数据
- **FR-036**: 盒子重置操作必须清除所有可能包含用户信息的缓存数据

**存储管理需求**

- **FR-037**: 盒子本地仅存储必要的系统数据:固件、系统提示音、多个WiFi凭证(加密存储,最多20个)、设备状态
- **FR-038**: 盒子不得存储对话历史、用户行为日志、或任何可累积增长的用户数据
- **FR-039**: 盒子的日志功能(如有)必须采用循环日志机制,日志文件总大小不得超过100KB,自动覆盖最旧记录
- **FR-040**: 盒子在存储WiFi凭证达到上限(20个)时,自动覆盖最久未使用的网络

### 3.2 多模态反馈交互增强需求

**设计理念**: 通过预设音效和震动反馈增强设备"生命感",在未被语音或晃动唤醒时提供主动反馈,无论在线或离线状态都能保持基本交互体验。

- **FR-041**: 盒子在检测到IMU动作时(如轻拍、温柔摇晃、翻转等),若当前未被语音唤醒或晃动唤醒,则必须播放预设的非语言音效(如好奇的"嗯?"、开心的哼唱)并触发对应的震动反馈,而非保持沉默
  - **触发条件**: 不限于离线状态,在线状态下若未被语音/晃动唤醒也应触发此反馈
  - **震动反馈**: 结合音效播放对应震动模式
  - **硬件要求**: 盒子必须配备偏心转子振动电机(ERM或LRA),通过GPIO驱动,支持震动强度(PWM占空比)和模式(震动时长、间隔)控制
- **FR-042**: 盒子必须支持为不同玩具角色配置专属音效库和震动模式库
- **FR-043**: 盒子被拿起时(检测到"拿起"动作),若未被语音/晃动唤醒,应播放简短的问候音效并配合轻微震动,而非完全无响应
  - **区别于FR-030a**: FR-030a针对休眠状态的唤醒,本条针对待机状态的主动反馈
- **FR-044**: 预设音效和震动反馈的优先级应低于系统提示音和AI语音,但高于沉默状态
  - **存储要求**: 总音效数量≤10个,Flash占用<500KB
  - **震动模式**: 预设震动模式≤10种,存储占用<10KB

### 3.3 多语言支持需求

**设计理念**: 支持中英文系统提示语音,通过云端配置或固件配置灵活选择语言版本,满足国内外不同市场需求。

- **FR-045**: 盒子必须支持中文和英文两种语言的系统提示音,包括所有FR-021定义的提示音类型
- **FR-046**: 盒子必须在固件烧录阶段通过menuconfig配置默认语言版本(中文版/海外版),烧录后系统提示音默认使用对应语言
- **FR-047**: 盒子必须支持通过云端配置动态切换系统提示音语言,云端可针对特定批次设备标识目标市场(如"海外市场"),设备联网后自动下载并切换至对应语言的提示音
- **FR-048**: 云端语言配置优先级高于固件默认配置,即:若云端配置了语言版本,设备联网后自动应用云端配置;若云端未配置,则使用固件默认语言
- **FR-049**: 系统提示音语音包必须支持热更新,设备联网后可从云端下载新语言包并替换本地提示音,无需重新烧录固件
- **FR-050**: 语音包文件必须采用OGG格式Opus封装,每种语言的完整语音包大小≤1MB,支持中英文两种语言时总占用≤2MB

**实现说明**:
- 固件menuconfig提供语言选项: `CONFIG_LANG_CN`(中文版) / `CONFIG_LANG_EN`
- 云端通过设备配置API下发语言标识,设备在联网时查询并应用
- 语音包存储在Flash独立分区,支持动态替换

### 3.4 OTA固件升级需求

**设计理念**: 支持安全、可靠的空中固件升级,通过灰度发布降低升级风险,确保设备可持续迭代优化。

- **FR-051**: 盒子必须支持OTA(Over-The-Air)固件升级功能,采用ESP-IDF原生OTA方案:
  - **双分区方案**: Flash划分为ota_0和ota_1两个应用分区,支持A/B分区切换
  - **升级触发**: 设备定期(每24小时)向云端查询固件更新,或用户通过APP主动触发升级检查
  - **版本校验**: 云端返回固件版本号、文件大小、MD5/SHA256校验和,设备对比本地版本判断是否需要升级
  - **下载方式**: 通过HTTPS从云端下载固件到非活动分区
  - **断点续传**: 支持固件下载断点续传,网络中断后可从上次下载位置继续,避免重复下载
- **FR-052**: 盒子必须支持**灰度发布**机制,由云端控制升级策略:
  - **设备分组**: 云端根据设备ID、固件版本、地域等维度将设备分组
  - **灰度比例**: 云端配置灰度升级比例(如5% → 20% → 50% → 100%),设备请求升级时,云端根据比例决定是否下发升级包
  - **灰度标识**: 设备上报唯一标识(MAC地址或设备ID),云端根据哈希算法或白名单判断设备是否在灰度范围内
  - **升级控制**: 若设备不在当前灰度范围,云端返回"暂无可用更新",设备继续使用当前版本
  - **紧急停止**: 云端可随时停止灰度发布,已下载未安装的设备不执行升级
- **FR-053**: 盒子在执行OTA升级时必须保证安全性和用户体验:
  - **电量检查**: 升级前检查电量,电量<30%时拒绝升级并提示"电量不足,请充电后再升级"
  - **充电状态**: 允许在充电状态下升级(优先场景),非充电状态电量≥50%时也允许升级
  - **用户确认**: 检测到新版本后,播放提示音"发现新版本固件,是否升级?"并通过APP通知用户,等待用户确认
  - **静默升级**: 云端可配置静默升级策略(在休眠状态且充电时自动升级),无需用户确认
  - **升级中提示**: 升级过程中LED呼吸灯闪烁,禁用所有交互功能(语音、按钮、IMU),播放提示音"固件升级中,请勿断电"
  - **进度上报**: 升级进度(0%-100%)实时上报云端,可在APP端显示
- **FR-054**: 盒子必须支持升级失败后的回滚机制:
  - **校验失败**: 固件下载完成后,验证MD5/SHA256校验和,不匹配则删除固件并提示"升级失败,请重试"
  - **启动失败**: 新固件启动失败(连续3次重启失败),自动回滚到旧版本固件
  - **回滚通知**: 回滚成功后,设备上报云端并通过APP通知用户"升级失败已回滚,当前版本:vX.X.X"
  - **版本标记**: 云端标记失败的固件版本,暂停对该设备的后续升级推送
- **FR-055**: 盒子在升级成功后必须执行以下操作:
  - **版本上报**: 重启后上报新版本号到云端,更新设备版本记录
  - **用户通知**: 播放提示音"固件升级成功,当前版本:vX.X.X",并通过APP推送通知
  - **配置保留**: 升级过程不影响WiFi凭证、用户配置、语言设置等NVS数据
  - **日志记录**: 记录升级时间、旧版本号、新版本号到循环日志
- **FR-056**: OTA升级过程必须遵循以下安全要求:
  - **固件签名**: 固件包必须包含数字签名,设备验证签名有效性后才执行升级
  - **HTTPS传输**: 固件下载必须通过HTTPS加密传输,验证服务器证书
  - **防回滚**: 禁止降级到低于最低安全版本的固件
  - **完整性校验**: 使用SHA256校验固件完整性,校验失败立即停止升级

### 3.5 网络切换与按钮识别需求

**设计理念**: WiFi+4G版提供灵活的网络切换能力,通过双击M键实现快速切换,并采用智能算法识别双击操作,避免与单击冲突。

- **FR-057 (WiFi/4G手动切换)**: WiFi+4G版必须支持用户通过双击M键在WiFi和4G之间手动切换:
  - **切换触发**: 在活跃状态下双击M键(两次点击间隔<500ms)
  - **提示音序列**:
    - 检测到双击后,立即播放"已切换至WiFi/4G模式"
    - 连接成功后,播放"网络连接成功"
  - **切换速度**: WiFi→4G切换在2秒内完成,4G→WiFi切换在3秒内完成
  - **对话中断**: 网络切换过程会中断正在进行的语音对话,切换完成后用户可重新发起对话
  - **永久生效**: 手动切换后,保持用户选择的网络模式,直到下次手动切换或重启设备
  - **LED指示**: WiFi模式LED蓝色常亮,4G模式LED绿色常亮,切换中LED紫色闪烁
  - **WiFi版说明**: WiFi版不支持网络切换,双击M键无响应
- **FR-058 (自动网络切换策略)**: WiFi+4G版必须采用简化的网络选择策略,避免运行中频繁切换:
  - **开机网络选择**(唯一的自动切换场景):
    - 优先尝试连接已保存的WiFi网络(按信号强度降序)
    - 若5秒内未连接WiFi成功,自动切换至4G网络
    - 网络选定后保持不变,不再自动切换
  - **网络断开处理**:
    - WiFi断开时: 尝试连接其他已保存WiFi,失败则切换至4G
    - 4G断开时: 尝试重连4G,失败则播放"网络连接失败"
  - **运行中稳定性**: 运行过程中不监控信号强度,不基于RSSI自动切换,避免网络抖动
  - **手动切换优先**: 用户可随时通过双击M键手动切换,手动选择永久生效直到下次手动切换或重启
- **FR-059 (双击识别算法)**: 盒子必须实现准确的双击识别算法,区分单击和双击操作:
  - **双击定义**: 两次按下释放,间隔时长<500ms,每次按下时长50-300ms
  - **识别策略**: 首次点击后启动300ms定时器,定时器内检测到第二次点击→识别为双击;定时器超时→识别为单击
  - **状态感知优化**: 休眠状态下首次点击立即唤醒(不等300ms),活跃状态下等待300ms判断单击/双击
  - **识别成功率**: 双击识别成功率≥95%(NFR-031),误识别率<5%
  - **防抖处理**: 单次按下时长<50ms视为抖动,>1秒视为长按,不计入双击判断
- **FR-060 (双击功能限制)**: 双击功能必须仅在特定状态下响应,避免误操作:
  - **活跃状态**: 双击有效,用于网络切换(4G版)或其他扩展功能
  - **休眠状态**: 双击无效,仅单击唤醒
  - **配网模式**: 双击无效,避免干扰配网流程
  - **升级模式**: 双击无效,升级过程禁用所有按钮交互
- **FR-061 (网络重连通知防打扰)**: WiFi和4G网络重连时必须遵循智能通知策略,避免弱网环境下频繁打扰用户:
  - **首次连接**: 开机后首次连接成功,总是播报"网络连接成功"
  - **网络切换**: WiFi和4G之间切换时,总是播报"已切换至WiFi/4G模式"
  - **短时重连(静默)**: 断线时长<2分钟,重连成功不播报提示音,静默恢复服务
  - **长时重连(播报)**: 断线时长≥2分钟,重连成功播报"网络连接成功"
  - **状态记录**: 固件需记录上次成功连接时间戳和断开连接时间戳,用于判断断线时长
  - **应用场景**: 适用于WiFi版和WiFi+4G版,避免电梯、地下室、信号边缘等弱网场景频繁提示

**实现说明**:
- 采用ESP-IDF esp_https_ota组件
- OTA分区配置: ota_0 (4MB) + ota_1 (4MB) + otadata
- 云端API: `/api/ota/check`(检查更新) + `/api/ota/download`
- 支持chunked下载,每次下载4KB-8KB数据块

### 3.6 关键实体

- **语音会话**: 表示一次完整的用户与AI的对话交互,包含动作上下文、时间戳等属性
- **网络配置**: 存储多个WiFi网络凭证(最多20个),每个包含SSID、密码(加密存储)、上次连接时间、信号强度等属性,持久化保存在设备本地
- **设备状态**: 表示盒子当前的运行状态,包含电量百分比、网络连接状态、蓝牙配对状态、充电状态、音频播放状态、温度状态等属性,运行时状态不持久化。设备状态需要上报云端,后续在APP端显示
- **用户动作**: 表示IMU传感器检测到的用户物理交互,包含动作类型(摇晃/翻转/轻拍/静置)、动作强度、时间戳等属性,实时传递给AI后不保存
- **系统提示音**: 预置的音频文件资源,包含提示音类型、音频文件路径、播放优先级等属性,固化在固件中
- **预设音效**: 用于多模态反馈的非语言音效文件(如"嗯?"、哼唱等),包含音效类型、文件路径、触发条件等属性,固化在固件中,总数≤10个
- **震动模式**: 预设的震动反馈模式参数,包含模式ID、震动时长(ms)、间隔时长(ms)、震动强度(PWM占空比%)等属性,固化在固件中,总数≤10种
- **OTA固件包**: 用于设备升级的固件二进制文件,包含版本号、文件大小、校验和(SHA256)、数字签名、下载URL等属性,存储在云端,由灰度发布策略控制下发
- **循环日志**: (可选)用于故障诊断的临时日志,固定大小100KB,采用循环覆盖机制,不保存用户隐私数据,包含OTA升级记录

## 4. 非功能性需求

本章节整合所有性能、可靠性、安全性和易用性相关的量化指标,为测试和运维团队提供明确的质量评估标准。

### 4.1 性能需求

**NFR-001 语音交互响应时间**
- **指标**: 用户说话结束到AI开始播放回应的端到端延迟 ≤ 2秒
- **测试条件**: 正常网络环境(延迟<100ms,丢包率<1%),WiFi信号≥-70dBm
- **降级策略**: 若网络延迟>200ms,允许延迟增至3秒;若延迟>5秒,直接放弃本次请求并播放提示音"网络延迟过高,请稍后再试"
- **关联需求**: SC-002, FR-019

**NFR-002 打断检测响应时间**
- **指标**: 检测到用户打断到停止播放的响应时间 ≤ 500毫秒
- **测试条件**: 双麦克风波束成形正常工作,环境噪音<60dB
- **技术实现**: 双麦克风阵列实时检测语音能量峰值,触发播放中断
- **关联需求**: SC-003, FR-017

**NFR-003 WiFi自动切换速度**
- **指标**: 当前WiFi信号丢失后,30秒内自动连接其他已保存网络
- **测试条件**: 至少保存2个可用WiFi,备用WiFi信号≥-75dBm
- **降级策略**: 若所有已保存WiFi不可用,仅在语音或摇晃唤醒时播放提示音"网络未连接,请前往小程序配网";用户可通过长按M键3秒手动进入配网模式
- **关联需求**: SC-005a, FR-014b, FR-011

**NFR-004 休眠与唤醒性能**
- **休眠触发**: 连续10分钟无交互自动进入休眠状态
- **休眠功耗**: 休眠功耗 ≤ 待机功耗的10%
- **唤醒速度**: 从休眠到可用状态 ≤ 2秒
- **关联需求**: SC-009, FR-028, FR-029, FR-030

**NFR-005 语音唤醒词性能**
- **唤醒词识别准确率**: ≥90%(在安静环境<40dB和中等噪音环境<60dB下测试)
- **误唤醒率**: <5%(在持续1小时的环境噪音或正常对话环境中,误唤醒次数<3次)
- **唤醒响应时间**: 从唤醒词说完到播放唤醒提示音 ≤ 500ms
- **功耗要求**: 待机状态下持续监听唤醒词功耗 ≤ 50mA @ 3.7V
- **唤醒距离**: 正常音量说话(60-70dB),1-3米距离内可靠唤醒
- **测试条件**:
  - 安静环境: 背景噪音<40dB
  - 中等噪音: 背景噪音40-60dB(如室内正常活动)
  - 嘈杂环境: 背景噪音>60dB(如电视播放、多人对话),允许识别准确率降至≥80%
- **超时机制**: 唤醒后15秒内无有效语音输入自动退出对话模式
- **关联需求**: FR-020

**NFR-009 IMU动作识别准确率**
- **指标**: 针对摇晃、翻转、轻拍三种主要动作,识别准确率 ≥ 85%
- **测试方法**: 每种动作重复测试20次,准确识别次数/总次数
- **误识别容忍**: 静置状态下误触发率 < 5%
- **关联需求**: SC-004, FR-004

**NFR-010 系统提示音及时性**
- **指标**: 系统事件触发后1秒内开始播放对应提示音
- **覆盖场景**: 开机/关机/充电/网络连接/电量警告等13种提示音
- **优先级**: 系统提示音优先级高于AI语音,播放时暂停AI输出
- **关联需求**: SC-008, FR-022, FR-023

### 4.2 可靠性需求

**NFR-011 WiFi连接成功率**
- **指标**: WiFi信号强度≥-70dBm时,连接成功率 ≥ 95%
- **测试样本**: 100次连接尝试
- **失败处理**: 连接失败播放提示音,保持蓝牙配对模式等待用户干预
- **关联需求**: SC-005, FR-013

**NFR-012 云端服务容错**
- **超时阈值**: 单次API请求超时阈值设为2秒
- **重试策略**: 请求失败或超时自动重试1次
- **降级提示**: 重试后仍失败,播放"服务暂时不可用,请稍后再试"
- **关联需求**: FR-019b

**NFR-013 充电安全与保护**
- **NTC温度传感器硬件规格**:
  - **传感器类型**: NTC热敏电阻(负温度系数),推荐阻值10kΩ @ 25°C或100kΩ @ 25°C
  - **安装位置**: NTC需紧贴电池表面或电池保护板PCB,确保准确测量电池温度
  - **精度要求**: 温度测量精度±2°C(在0-60°C范围内)
  - **读取方式**: 通过ESP32-S3的ADC引脚读取NTC分压电路电压,固件查表或公式计算温度值
  - **采样电路**: 建议使用10kΩ或100kΩ固定电阻与NTC组成分压电路,连接至ESP32-S3 ADC引脚(推荐ADC1_CH0-CH4)
  - **推荐型号**: EPCOS B57891M0103J000 (10kΩ, 1% 精度) 或类似规格NTC
- **温度监测**:
  - **监测频率**: 充电时实时监测电池温度,采样频率≥1次/秒
  - **监测范围**: 支持-20°C至+80°C温度测量范围(虽然电池安全范围限制在0-50°C)
  - **数据滤波**: 使用滑动平均或中值滤波(窗口≥3个采样点)消除瞬时噪声干扰
- **过温保护**: 温度>50°C立即停止充电(2秒内)并播放警告"温度过高,已停止充电",降至45°C自动恢复
- **滞环设计**: 5°C滞环(50°C停止/45°C恢复)防止频繁开关充电
- **多次超温**: 单次充电周期内连续3次超温保护触发(每次间隔<10分钟)后,停止充电并关机,需用户拔线冷却至少30分钟
- **阈值依据**: 基于Li-ion电池安全标准(推荐0-45°C,最高50°C)和ESP32实际应用经验,50°C阈值适合AI玩具使用场景
- **低温保护**(可选): 温度<0°C时建议停止充电或降低充电电流(0.1C),避免锂电池低温充电析锂风险
- **关联需求**: FR-027b, FR-027c

**NFR-014 多WiFi管理可靠性**
- **存储容量**: 最多支持保存20个WiFi网络凭证,超过上限时自动覆盖最久未使用的网络
- **自动选择**: 开机/断网时,优先连接信号最强的已保存网络
- **覆盖策略**: 达到上限时,支持APP删除旧网络或自动覆盖最久未使用网络
- **关联需求**: FR-014, FR-014a, FR-040

**NFR-014a WiFi信号可靠性与抗干扰测试**
- **信号强度稳定性测试**:
  - **测试条件**: WiFi信号强度在-70dBm至-50dBm范围内波动
  - **连接稳定性**: 连续运行30分钟,连接保持率≥99%
  - **测试样本**: 每个信号强度等级(-70dBm, -60dBm, -50dBm)测试10次
- **抗干扰能力测试**:
  - **2.4GHz同频干扰**: 在有5个以上邻近WiFi网络(同2.4GHz频段)的环境下,连接成功率≥90%
  - **蓝牙共存干扰**: WiFi和BLE同时工作时(如配网过程),WiFi吞吐量下降<20%,BLE配对成功率≥95%
  - **微波炉干扰**: 在微波炉工作(2.45GHz强干扰源,距离2米)时,WiFi连接保持率≥80%,若断开需在10秒内自动重连
  - **4G共存干扰**(仅WiFi+4G版): WiFi和4G同时工作时,WiFi吞吐量下降<15%,4G信号强度下降<3dBm
- **远距离性能测试**:
  - **测试条件**: 设备与WiFi路由器之间有2堵墙
  - **信号衰减**: 信号强度≥-75dBm时仍能保持稳定连接
  - **连接成功率**: ≥85%
- **快速重连测试**:
  - **测试场景**: 设备从WiFi覆盖区移出再移入
  - **重连时间**: 检测到WiFi信号恢复后5秒内完成重连
- **关联需求**: SC-005, NFR-010, FR-014b

**NFR-014b 蓝牙信号可靠性与抗干扰测试**
- **配对成功率测试**:
  - **测试条件**: 设备与手机距离1-10米,无明显障碍物
  - **配对成功率**: ≥98%
  - **配对时间**: 从搜索到配对成功≤15秒
- **抗干扰能力测试**:
  - **WiFi共存干扰**: BLE配对过程中WiFi扫描同时进行,配对成功率≥95%
  - **多蓝牙设备干扰**: 周围有5个以上活跃蓝牙设备(如手机、耳机、音箱),配对成功率≥90%
  - **2.4GHz频段拥挤**: 在WiFi密集环境(10个以上AP),BLE配对成功率≥85%
- **有效距离测试**:
  - **无障碍物**: 10米距离内配对成功率≥95%
  - **一堵墙障碍**: 5米距离内配对成功率≥90%
  - **信号衰减容忍**: RSSI低至-80dBm时仍能保持配对连接
- **数据传输可靠性**:
  - **WiFi凭证传输**: 在配对成功后,WiFi凭证传输成功率≥99%
  - **传输时间**: 单个WiFi凭证传输完成≤2秒
  - **错误重传**: 传输失败时自动重传,最多3次重试
- **关联需求**: FR-011, FR-012, FR-013

**NFR-014c 4G信号可靠性与抗干扰测试**
- **信号强度与连接稳定性**:
  - **测试条件**: 4G信号强度RSSI在-100dBm至-70dBm范围内
  - **连接稳定性**:
    - RSSI ≥ -90dBm: 连接保持率≥99%,数据传输成功率≥98%
    - RSSI在-100dBm至-90dBm: 连接保持率≥85%,数据传输成功率≥90%
  - **网络切换延迟**: 4G网络在不同基站间切换(小区切换),切换时间<3秒,语音数据包丢失率<5%
- **抗干扰能力测试**:
  - **WiFi/BLE共存**: 4G、WiFi、BLE三模同时工作时:
    - 4G吞吐量下降<10%
    - WiFi吞吐量下降<15%
    - BLE配对成功率≥95%
  - **天线隔离要求**: PCB设计需保证4G天线与WiFi/BLE天线隔离度≥20dB,减少互相干扰
  - **金属屏蔽干扰**: 设备放置在金属桌面或靠近金属物体时,4G信号强度下降<5dBm
- **弱信号性能测试**:
  - **测试场景**: 室内深处、地下室、电梯等弱信号环境
  - **最低可用信号**: RSSI ≥ -105dBm时仍能建立连接
  - **数据传输**: RSSI在-100dBm时,上行语音数据传输成功率≥85%
- **网络切换逻辑测试**:
  - **开机WiFi优先**: 开机时优先尝试连接WiFi,若5秒内未连接成功则自动切换至4G
  - **运行中保持**: 运行过程中保持当前网络连接,不基于信号强度自动切换
  - **手动切换**: 用户可通过双击M键手动切换WiFi/4G,手动选择永久生效直到下次手动切换或重启
  - **断线处理**: WiFi断开时尝试连接其他已保存WiFi,失败则切换至4G;4G断开时尝试重连
  - **切换提示**: 手动切换时播放"已切换至WiFi/4G模式"+"网络连接成功",自动断线切换不播放提示音
- **eSIM管理**:
  - **Profile下载**: 支持OTA下载eSIM Profile,下载成功率≥95%
  - **多Profile管理**: 支持存储≥2个eSIM Profile,切换时间<10秒
- **功耗要求**:
  - **活跃状态**: 4G数据传输时功耗<200mA @ 3.7V
  - **休眠状态**: 4G模块休眠(WiFi可用时)功耗<10mA @ 3.7V
  - **待机状态**: 4G已连接但无数据传输时功耗<50mA @ 3.7V
- **关联需求**: 1.4硬件版本规划, NFR-013a

### 4.3 安全性需求

**NFR-015 数据传输加密**
- **加密协议**: 所有网络通信必须使用TLS/SSL加密
- **证书验证**: 云端API通信需验证服务器证书,防止中间人攻击
- **覆盖范围**: 语音数据上传、AI回应下载、配置同步等所有网络交互
- **关联需求**: FR-034

**NFR-016 零用户数据存储**
- **设备端**: 不存储任何用户语音数据
- **云端**: 语音数据处理完成后立即删除,不保留任何记录或日志
- **审计要求**: 可通过代码审计和网络流量监控验证合规性
- **关联需求**: FR-035, FR-036, 数据隐私原则

**NFR-017 WiFi凭证保护**
- **加密存储**: WiFi密码使用AES-256加密后存储于NVS分区
- **访问控制**: 仅授权固件模块可访问加密凭证,禁止外部读取
- **重置清除**: 恢复出厂设置时完全清除所有加密凭证
- **关联需求**: FR-031, FR-036

### 4.4 易用性需求

**NFR-020 首次使用体验**
- **指标**: 用户从开机到完成首次语音对话(含配网)总时长 ≤ 3分钟
- **无说明书操作**: 90%的用户能够在无说明书情况下独立完成首次配网
- **引导提示**: 通过系统语音提示引导用户完成开机、配网、首次对话
- **关联需求**: SC-001, SC-007

**NFR-021 续航与电源体验**
- **续航时间**: 中等使用强度(每小时对话10分钟)下,单次充电续航 ≥ 6小时
- **低电量提醒**: 电量<15%时每5分钟播放一次提醒,<5%时自动关机前提醒
- **充电反馈**: 充电状态变化时及时播放提示音
- **关联需求**: SC-006, FR-024, FR-025, FR-026, FR-027

**NFR-022 交互反馈清晰度**
- **语音提示**: 所有系统事件(开机/关机/充电/网络/错误)均有对应语音提示
- **音效区分**: 成功/失败/警告等不同类型事件使用可区分的音效设计
- **音量适中**: 系统提示音音量适中,不刺耳,符合家庭使用场景
- **关联需求**: FR-021, FR-022, NFR-009

### 4.5 可维护性需求

**NFR-023 日志与诊断**
- **循环日志**: 采用固定100KB循环日志,自动覆盖最旧记录
- **隐私保护**: 日志仅包含系统事件和错误信息,不记录用户语音或对话内容
- **故障诊断**: 记录网络连接失败、API超时、传感器异常等关键事件
- **关联需求**: FR-039, 关键实体-循环日志

**NFR-024 设备重置可靠性**
- **完整清除**: 重置操作清除所有WiFi凭证、配置和缓存数据
- **保留固件**: 重置不影响固件和系统提示音资源
- **重置确认**: 重置操作需特定长按时长(10秒),避免误触发
- **关联需求**: FR-031, FR-032, FR-033

### 4.6 硬件约束与技术指标

**NFR-025 双麦克风阵列规格**
- **硬件配置**:
  - **ADC芯片**: ES7210
  - **麦克风型号**: LMA3729T381-OY3S × 2
  - **麦克风间距**: 45mm
  - **轴线要求**: 麦克风轴线应平行于水平线
  - **物理隔离**: 麦克风应远离扬声器,与扬声器音腔之间通过橡胶垫等材料隔离缓冲,减少振动干扰
- **音频参数**:
  - **采样率**: 16kHz
  - **位深度**: 24bit
  - **频率响应**: 50~16 KHz范围内波动应在 ±3 dB以内
  - **最大声压级**: 麦克风拾音声压 ≤ 102 dB
  - **信噪比**: ≥60dB
- **算法功能**:
  - **回声消除(AEC)**: 必须基于乐鑫(Espressif)官方AEC组件实现,支持扬声器播放时麦克风回声消除,防止循环反馈,确保打断(Barge-in)功能可靠性
    - **AEC参考信号**: 从DA后级、PA(NS4150B)前级回采
    - **功放THD要求**: 100Hz<10%, 200Hz<6%, 350Hz以上<3%
  - **波束成形**: 利用双麦克风相位差(45mm间距)进行方向性增强,抑制侧向噪音,实现声源识别
  - **噪声抑制**: 环境噪音<60dB时,能有效提取人声信号
  - **打断检测**: 基于AEC处理后的语音能量检测,在扬声器播放期间实时监测用户语音输入
- **详细参考**: 见第9章技术参考文档

**NFR-026 IMU传感器动作定义**

*注: 以下参数为初步定义,详细实现应参考Project Magic项目的经验数据*

- **拿起检测**: 三轴合成加速度从静置状态(<0.2g)突然上升至>0.5g并持续>500ms,识别为拿起动作,用于休眠唤醒或主动问候
- **摇晃检测(快速)**: X/Y轴加速度变化频率>2Hz,振幅>1.0g,持续时间≥1秒,识别为快速摇晃,可用于唤醒或触发兴奋回应
- **摇晃检测(温柔)**: X/Y轴加速度变化频率1-2Hz,振幅0.3-1.0g,持续时间≥2秒,识别为温柔摇晃,触发温和回应
- **翻转检测**: Z轴角度变化≥180°,速率适中(0.5-2秒完成翻转),识别为翻转
- **轻拍检测**: Z轴加速度瞬时峰值>1.5g,出现2次明显峰值(间隔<500ms),识别为轻拍
- **跌落检测**: 三轴合成加速度同时接近0g(自由落体),持续>100ms,识别为跌落,触发安抚性回应
- **静置检测**: 三轴加速度变化<0.1g持续≥30秒,识别为静置
- **组合动作**: 连续识别多个动作(如摇晃+翻转),触发特殊反馈或彩蛋
- **算法参考**: 详细阈值调优和滤波算法应参考Project Magic项目的实现经验

- **EN 71-2**: 易燃性(玩具材料不得易燃)
- **EN 71-3**: 特定元素的迁移(19种重金属含量限制,如铅≤13.5mg/kg)
- **EN 62115**: 电玩具安全标准(电气安全、温升测试、电池保护)
- **硬件影响**: 与ASTM F963类似,电池舱需工具打开,避免小零件设计

**标识与包装要求**:
- 产品需标注: CE标志、制造商信息、符合性声明
- 说明书需包含: 多语言操作指南(至少英文+目标市场语言)、安全警告、CE合规声明、废弃处置说明(WEEE标志)

**四、硬件设计综合影响**

为满足上述四大认证(CCC/SRRC/FCC/CE),硬件设计需综合考虑以下要点:

**4.1 射频(RF)设计**
- **天线设计**: WiFi/BLE/4G天线需满足各国频段和增益要求,推荐使用PCB天线或陶瓷天线(增益<3dBi)
- **功率控制**: ESP32-S3 WiFi/BLE发射功率需通过固件限制在各国允许范围内(中国≤20dBm, 美国≤30dBm, 欧盟≤20dBm)
- **信道限制**: 固件需支持区域配置,根据销售地区启用对应WiFi信道(中国1-13禁用12-13, 美国1-11, 欧盟1-13)
- **4G模组选型**: 选择支持多频段的CAT1模组,至少覆盖中国(B1/B3/B5/B8/B34/B38/B39/B40/B41)、美国(B2/B4/B5/B12/B13)、欧盟(B1/B3/B7/B8/B20/B28)主流频段

**4.2 EMC/EMI设计**
- **PCB布线**:
  - 高速信号(SPI/I2S)走线需短且紧凑,阻抗匹配
  - 电源和地平面完整,减少环路面积
  - 敏感信号(ADC/麦克风)远离高速信号和射频模块
- **滤波器件**:
  - 电源线增加磁珠和滤波电容(如1μF+0.1μF+10pF三级滤波)
  - USB-C接口增加共模扼流圈(CMC)和TVS二极管
  - WiFi/BLE/4G模块电源和信号线增加π型滤波器
- **屏蔽设计**: WiFi/BLE模块和敏感模拟电路可增加屏蔽罩,减少辐射和干扰
- **接地设计**: 数字地、模拟地、射频地分离,通过磁珠或0Ω电阻单点接地

**4.3 电气安全设计**
- **绝缘距离**: 不同电位导体间爬电距离≥3mm,电气间隙≥1mm
- **过压保护**: USB-C接口增加TVS二极管(如USBLC6-2SC6),防止静电和浪涌
- **过流保护**: 电池充电和放电回路增加保险丝(如可恢复保险丝PPTC,额定电流1A)
- **电池保护**: 锂电池保护板需具备过充(4.25V)、过放(2.5V)、过流(>2C)、短路保护功能
- **温度保护**: NTC温度传感器监测电池温度,>50°C停止充电(NFR-013已定义)

**4.4 机械强度与阻燃设计**
- **外壳材料**: 选择UL94 V-1或V-0级阻燃塑料(如ABS+PC合金,阻燃等级V-0)
- **跌落测试**: 产品需通过1.5m高度6面跌落测试,外壳和内部结构需加强设计
- **电池舱设计**: 电池舱需螺丝固定或特殊卡扣(需工具打开),防止儿童徒手打开
- **防水防尘**(可选): 若产品需要防水防尘,建议达到IP54等级(防尘防溅水)

**4.5 材料与环保合规**
- **无铅工艺**: 所有电子元器件和焊接工艺使用无铅材料(Lead-Free, RoHS compliant)
- **塑料材料**: 外壳、按钮、线缆绝缘层不含邻苯二甲酸酯增塑剂、多溴联苯阻燃剂
- **重金属限制**: 确保材料中铅/镉/汞/六价铬/砷/硒等重金属含量符合RoHS/REACH/ASTM F963/EN 71-3限值

**五、固件与软件影响**

**5.1 区域配置与功率控制**
- 固件需支持区域配置参数(中国/美国/欧盟等),根据销售地区自动或手动配置:
  - WiFi信道范围(中国1-13禁用12-13, 美国1-11, 欧盟1-13)
  - WiFi/BLE发射功率限制(中国/欧盟≤20dBm, 美国≤30dBm)
  - 4G模组频段锁定(根据地区启用对应LTE频段)
- ESP32-S3通过`esp_wifi_set_country()`API设置WiFi国家代码,自动限制信道和功率

**5.2 OTA升级与固件签名**
- 固件升级需支持数字签名验证,防止非法固件刷入(避免用户自行修改导致认证失效)
- OTA升级不得修改区域配置和功率限制参数(或需重新认证)

**关联需求**: 6.2业务约束, 硬件设计需满足上述所有认证标准

**NFR-033 双眼屏幕GPIO技术规格**
- **接口类型**: SPI或I2C,推荐SPI以支持更高刷新率和更流畅的动画效果
- **SPI引脚分配**(推荐方案):
  - **SCLK (时钟)**: GPIO18 (推荐,SPI2默认引脚)
  - **MOSI (数据)**: GPIO23 (推荐,SPI2默认引脚)
  - **CS左眼 (片选)**: GPIO5 (推荐)
  - **CS右眼 (片选)**: GPIO15 (推荐)
  - **DC (数据/命令)**: GPIO17 (推荐)
  - **RST (复位,可选)**: GPIO16 (推荐)
  - **背光控制 (可选)**: GPIO19 (推荐,支持LEDC PWM调光)
  - **总引脚数**: 7路GPIO (最少5路,推荐7路含RST和背光控制)
- **I2C引脚分配**(备选方案):
  - **SCL (时钟)**: GPIO22 (I2C默认引脚)
  - **SDA (数据)**: GPIO21 (I2C默认引脚)
  - **总引脚数**: 2路GPIO
- **引脚选择原则**:
  - 避免与核心功能冲突:不使用I2S音频引脚(GPIO0-GPIO14中的部分引脚)、触摸引脚、strapping引脚等
  - 优先使用GPIO16-GPIO23等灵活复用引脚
  - CS引脚需支持GPIO输出,可使用任意可用GPIO
  - 背光控制引脚需支持LEDC PWM功能(ESP32-S3大部分GPIO均支持)
- **SPI通信参数**(推荐配置):
  - **时钟频率**: 10-40 MHz (取决于屏幕驱动IC规格,如ST7735/ST7789可支持40MHz)
  - **数据位宽**: 8位
  - **工作模式**: SPI Mode 0 或 Mode 3 (取决于屏幕驱动IC)
  - **数据传输**: 仅MOSI单向传输(MISO不需要)
- **I2C通信参数**(备选配置):
  - **时钟频率**: 100kHz (标准模式) 或 400kHz (快速模式)
  - **地址**: 取决于屏幕驱动IC (如SSD1306默认0x3C或0x3D)
- **屏幕规格参考**:
  - **推荐尺寸**: 0.96-1.3英寸圆形或椭圆形OLED/TFT屏幕
  - **推荐分辨率**: 128×128像素(小尺寸OLED) 或 240×240像素(TFT彩屏)
  - **推荐驱动IC**:
    - OLED: SSD1306 (I2C/SPI, 单色), SSD1351 (SPI, 彩色)
    - TFT: ST7735 (SPI, 1.8英寸), ST7789 (SPI, 1.3英寸), GC9A01 (SPI, 1.28英寸圆形)
  - **供电电压**: 3.3V或5V (取决于屏幕模块,ESP32-S3可提供3.3V和5V输出)
  - **工作电流**: 单屏≤50mA (OLED), ≤100mA (TFT背光全亮)
  - **显示内容**: 眼睛表情动画(开心、困惑、眨眼、闭眼、左看右看等)
- **PCB设计要求**:
  - **引脚引出方式**: 引出至2.54mm排针接口或焊盘,便于焊接屏幕模块或排线连接
  - **电源与地线**: 需同时引出3.3V和GND (如屏幕需5V则额外引出5V)
  - **布线要求**: SPI信号线建议短距离走线(<10cm),保持信号完整性;如需长距离连接建议使用屏蔽排线
  - **接口防呆设计**: 建议使用防反插接口(如JST-PH或JST-SH连接器)
- **固件驱动要求**:
  - **驱动库**: 使用ESP-IDF SPI主机驱动或I2C主机驱动
  - **显示库**: 可使用LittlevGL (LVGL), U8g2, TFT_eSPI等开源图形库
  - **帧率要求**: ≥10 FPS (保证眨眼等动画流畅),推荐≥30 FPS
  - **内存占用**: 单屏显存≤10KB (128×128单色), ≤115KB (240×240全彩,16位色)
  - **刷新方式**: 支持局部刷新或全屏刷新,减少SPI传输数据量
- **功耗估算**:
  - **OLED屏**: 单屏平均功耗≤50mA @ 3.3V (显示内容越多功耗越高)
  - **TFT屏**: 单屏平均功耗≤100mA @ 3.3V (含背光,可通过PWM调光降低功耗)
  - **双屏总功耗**: ≤200mA @ 3.3V (两块TFT屏全亮)
  - **节能策略**: 建议在待机/休眠状态关闭屏幕或降低亮度,降低整机功耗
- **扩展性说明**:
  - 双眼屏幕为可选扩展功能,不影响基本语音交互功能
  - 如不连接屏幕,预留的GPIO可用于其他扩展功能(如LED灯条、额外传感器等)
  - 固件需支持屏幕插拔检测或配置开关,自动启用/禁用屏幕驱动
- **关联需求**: FR-009 (双眼屏幕GPIO预留)

## 6. 假设与依赖

### 6.1 技术假设

1. **AI服务可用性**: 假设存在可用的云端AI对话服务API,盒子通过WiFi网络访问该服务获取对话回应
2. **手机APP/小程序就绪**: 假设配套的手机APP或微信小程序已开发完成,能够提供蓝牙配对和WiFi配置功能
3. **语音识别与合成**: 假设采用行业标准的语音识别(ASR)和语音合成(TTS)服务,识别准确率和合成质量达到商用水平
4. **电池容量**: 假设盒子配备1200mAh锂聚合物电池,能够满足NFR-020定义的续航要求
5. **网络依赖**: AI对话服务完全依赖互联网连接,离线状态下通过预设音效和震动反馈保持基本交互体验
6. **单用户使用**: 假设盒子主要为单个用户设计,不需要支持多用户账户或个性化配置
7. **存储容量**: 假设ESP32S3模组配备足够的Flash存储空间(≥16MB),能够容纳固件、系统提示音和必要的系统数据,详见NFR-027
8. **环境噪音处理**: 假设双麦克风阵列具备基本的噪音抑制和回声消除能力,能够在典型家庭环境(噪音<60dB)下正常工作,详见NFR-024
9. **数据隐私**: 所有语音数据通过加密连接传输,处理后立即删除不保留,遵循中国《个人信息保护法》等相关隐私保护规定,详见NFR-015, NFR-017

### 6.2 依赖与约束

**外部依赖**

- 云端AI对话服务API的可用性和响应速度 → 详见NFR-011
- 手机APP/微信小程序的蓝牙和WiFi配置功能
- 用户家庭2.4GHz WiFi网络的可用性和稳定性 → 详见NFR-029
- 语音识别(ASR)和语音合成(TTS)第三方服务

**技术约束**

- ESP32S3模组的计算能力和存储空间限制 → 详见NFR-027
- **双麦克风阵列**: 阵列的噪音抑制和打断检测能力,必须基于乐鑫(Espressif)官方提供的AEC(Acoustic Echo Cancellation/声学回声消除)功能组件进行开发。这旨在确保在扬声器播放AI语音或其他音频时,依然能有效消除回声,准确捕捉用户的语音输入,从而实现可靠、低延迟的"打断"(Barge-in)功能 → 详见NFR-024
- 内置扬声器的音质和音量输出能力
- **IMU传感器**: 精度和采样频率要求,动作识别算法详细设计应参考Project Magic项目的相关定义与实现 → 详见NFR-025, FR-004a
- 蓝牙配对距离限制(典型<10米) → 详见NFR-029

**业务约束**

- **产品安全与认证要求**: 产品必须通过以下国际市场强制性认证,详见NFR-032:
  - **中国市场**:
    - CCC认证(中国强制性产品认证): 电气安全、机械强度、防火阻燃、温升测试等
    - SRRC认证(无线电型号核准): WiFi 2.4GHz、BLE、4G LTE频段和功率限制
    - 锂电池需通过GB 31241-2014认证
  - **美国市场**:
    - FCC认证: Part 15 Subpart B/C (EMI/无线射频), Part 22/24/27 (4G LTE,如适用)
    - UL/ETL安全认证(推荐): UL 62368-1电气安全, UL 2054/1642锂电池安全
    - 儿童玩具安全认证(如适用): CPSIA, ASTM F963 (小零件、重金属、易燃性)
  - **欧盟市场**:
    - CE认证(欧盟合格声明):
      - RED指令 2014/53/EU (无线电设备): EN 301 489, EN 300 328
      - LVD指令 2014/35/EU (低电压): EN 62368-1, EN 62133
      - EMC指令 2014/30/EU (电磁兼容): EN 55032, EN 55035
      - RoHS指令 2011/65/EU (有害物质限制): 铅/汞/镉/六价铬/PBB/PBDE/邻苯二甲酸酯限值
      - REACH法规: SVHC高度关注物质≤0.1%
    - EN 71玩具安全标准(如适用): EN 71-1/2/3, EN 62115
- **隐私合规要求**: 数据处理需符合中国《个人信息保护法》、欧盟GDPR等隐私保护规定 → 详见NFR-015, NFR-017
- **硬件设计约束**:
  - 外壳材料需使用UL94 V-1/V-0级阻燃塑料,符合RoHS/REACH无铅无害要求
  - 电池舱需螺丝固定或工具打开设计,防止儿童徒手打开
  - PCB需通过EMC测试(辐射/传导发射,ESD抗扰度),可能需增加滤波器件和屏蔽设计
  - WiFi/BLE天线增益≤2.5dBi,4G天线增益≤3dBi
  - 固件需支持区域配置(中国/美国/欧盟),自动限制WiFi信道和发射功率

## 7. 范围界定

### 7.1 包含在内

- 完整的语音对话交互功能
- **语音唤醒词**: 支持"Hello 灵犀"唤醒词,在待机状态下通过语音启动对话
- 蓝牙配对和WiFi配网流程
- 多WiFi网络管理与自动切换
- 基本的电源管理
- IMU动作识别与AI对话的结合
- 系统提示音和引导语音
- 多语言支持(中英文系统提示音,支持固件配置和云端动态切换)
- **多模态反馈**: 预设音效和震动反馈,在未被语音/晃动唤醒时提供主动反馈
- 设备重置功能
- 打断检测功能
- **触摸引脚预留与可选支持**: 硬件预留ESP32S3触摸引脚,支持外接铜箔实现触摸交互(可选功能,不影响基本功能)
- **双眼屏幕GPIO预留与可选支持**: 硬件预留SPI/I2C接口GPIO引脚,支持外接双眼屏幕(0.96-1.3英寸OLED/TFT)实现AI玩具表情显示(可选功能,不影响基本语音交互功能)
- **OTA固件升级**: 支持空中固件升级,包括灰度发布、版本回滚、升级进度反馈等完整功能

### 7.2 明确排除

- 盒子本地的AI模型运行
- 5GHz WiFi或以太网支持
- 触摸屏
- 额外的独立物理按钮
- 多设备组网或设备间通信
- 内容过滤或使用时长限制功能
- 与其他智能家居设备的联动

## 9. 技术参考文档

### 9.1 音频前端设计

#### 音频硬件选型方案

**完整音频链路**:
```
[用户语音] → [LMA3729T381麦克风×2] → [ES7210 ADC] → [ESP32S3 I2S] → [云端ASR]
[云端TTS] → [ESP32S3 I2S] → [ES8311 DAC] → [NS4150B功放] → [XHXDZ-2828扬声器] → [用户]
```

**音频采集链路**:
- **麦克风**: LMA3729T381-OY3S × 2
  - 间距: 45mm
  - 用途: 双麦克风阵列,支持声源识别和波束成形
- **ADC芯片**: ES7210
  - 接口: I2S连接至ESP32S3
  - 采样率: 16kHz
  - 位深度: 24bit
  - 通道: 使用2通道连接双麦克风,预留2通道可扩展

**音频输出链路**:
- **Codec芯片**: ES8311
  - 接口: I2S连接至ESP32S3
  - DAC: 24位,支持8k-96kHz采样率
  - 输出: 差分输出至NS4150B功放
  - AEC回采: ADC可回采PA前级参考信号用于AEC算法
- **功放芯片**: NS4150B
  - 输出功率: 3W @ 4Ω
  - 效率: >85%
  - 保护: 过温/短路/欠压保护
  - THD: 符合AEC要求
- **扬声器**: XHXDZ-2828-4R3W-2P
  - 尺寸: 28×28mm方形超薄
  - 阻抗: 4Ω
  - 功率: 3W
  - 频响: 300Hz-12kHz

**选型优势**:
1. **低功耗**: ES8311和NS4150B均为低功耗设计,延长电池续航
2. **高集成度**: ES7210支持4通道,预留扩展空间
3. **AEC友好**: ES8311 ADC可回采参考信号,配合乐鑫AEC算法实现可靠打断
4. **紧凑体积**: XHXDZ-2828超薄扬声器适合毛绒玩具内部空间

**乐鑫麦克风设计指南**
- **文档链接**: [Espressif Microphone Design Guidelines]
- **关键设计参数**:

#### 麦克风阵列间距
- **双麦克风方案**: 麦克风间距应保持 **4~6.5 cm**
- **轴线要求**: 麦克风轴线应平行于水平线
- **本项目采用**: 双麦克风阵列,间距范围 40-65mm

#### 麦克风与扬声器布局
- **隔离要求**: 麦克风应远离扬声器等会产生噪音或振动的物体
- **缓冲设计**: 麦克风与扬声器音腔之间应通过橡胶垫等材料隔离缓冲
- **目的**: 减少扬声器振动对麦克风的物理干扰,提升AEC效果

#### 音频技术参数
- **频率响应**: 50~16 KHz范围内波动应在 ±3 dB以内
- **最大声压级**: 麦克风拾音声压不应超过 102 dB
- **本项目采用**: 16kHz采样率,频响范围覆盖300Hz-12kHz

#### AEC回声消除硬件设计
- **参考信号采集**: 应尽量靠近扬声器侧,推荐从DA后级、PA(功率放大器)前级回采
- **功放THD要求**: 最大音量下
  - 100Hz: THD < 10%
  - 200Hz: THD < 6%
  - 350Hz以上: THD < 3%
- **D类功放滤波**: 从D类功放引参考信号时,需增加低通滤波器,截止频率推荐 > 22 KHz
- **本项目影响**: 确保AEC算法能准确消除扬声器回声,实现可靠的打断(Barge-in)功能
